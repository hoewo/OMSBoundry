# Project Directory v1

问题 A → 可验证结果 B：客户项目列表被截断为最新 100 条、项目包扁平化且返回丢失位置 → 通过有界分页读取 Project 自有目录，在同一工作台恢复原 OA 的层级、搜索和导航上下文。

## 不变量

- 新的只读 `GET /api/v1/project-directory` 不改变旧 `GET /api/v1/projects` 的 limit、排序、鉴权或响应契约。
- 目录仅包含已立项 `active` 项目、自有层级和当前经营／生产 Assignment 显示快照；不读取其他应用表，不写 Project revision、历史或业务事实。
- `project-workspace.read`、Tenant 和 Scope 来自已验证的 IAM Credential。租户级凭证可见该租户目录；资源级凭证只见签名 Resource IDs。客户端不能提交或扩大授权范围。
- 有权读子项目、无权读父项目时，子项目作为可见根展示，不泄漏父项目名称、编号、负责人或其他子项目。已授权父项目的子项目仍单独受同一 Scope 过滤。
- 分页计数的是可见根；搜索名称／编号时，匹配可见子项目会保留已授权父项目上下文，展开时显示该父项目下全部已授权 active 子项目。关键词是字面包含，不把 `%`、`_` 当作 SQL 通配符。
- 单次目录读取在只读 repeatable-read 事务内完成，根、子项目、当前 Assignment 和 total 同一快照；每页 1～100 根，offset 非负。跨页不是冻结的业务快照，消费端必须检查 total、重复 ID 和进度，变化时显式重新读取，不能静默截断。
- OA 编号年份／序号解析只在版本化参考 OA Customer Overlay 页面中执行，按原源码的编号规则，不按承接日期分组、不往 Base schema 增加客户年份字段。无年份编号的项目显式归入“未按年份编号”，避免隐藏已立项项目包。
- 浏览器 sessionStorage 只保存租户＋账号隔离的搜索、视图、页码、展开 ID 和滚动位置，不保存项目事实、金额、凭证或密码。直接从侧栏进入列表重置；详情返回和浏览器历史恢复上下文。

## 验收

真实 PostgreSQL 覆盖超过 100 根、分页 total、层级／搜索、Tenant、资源 Scope 父子双向隔离、Assignment 和零写入。HTTP 覆盖无凭证、缺能力、非法分页、客户端伪造 Scope 和旧接口兼容。前端覆盖原编号解析、分页／年份切换、搜索时机、包展开、返回／刷新／浏览器历史和失败重试；浏览器替身证据必须与真实持久化证据分开。

## 本批不负责

经营／生产进度筛选、金额、资料、合同、奖金等需各事实所有者的版本化只读投影接通，不能以 Project 临时字段或假数据填充。本批不证明完整 OA 或公网主站已经通过。
