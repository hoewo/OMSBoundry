# 客户场景边界证据

## 元信息

- 路径：`spec/assembly/customer-scenario-evidence.md`
- 所属模块：`assembly`
- 状态：🟢 已实现
- 优先级：P0
- 依赖规格：`demo-validation-2.md`
- 关联技术：`tech/assembly/scenario-evidence-validation.md`

## 问题与结果

**问题 A**：六层定制化方法和首个参考 OA 账目已经成立，但第二个场景如果继续以自由文本记录，参考材料、真实客户确认、实现证据和产品结论容易被混为一谈，无法稳定比较，也无法阻止客户专项侵入核心后仍被标记为通过。

**可验证结果 B**：每个候选场景使用同一份版本化证据契约记录问题、可观察结果、事实所有者、生命周期、纠错、启用应用、差异归层、连接器语义、边界信号和验收证据；自动校验对缺证据、越界和夸大结论失败关闭。

该契约只约束证据表达和结论门槛，不替代客户访谈、业务建模、客户确认或跨场景产品判断。

## 证据身份

每份账目只有一种来源身份：

| 来源 | 允许主张 | 禁止主张 |
| --- | --- | --- |
| `reference_product` | 当前参考产品基线通过 | 真实客户已接受、跨客户边界成立 |
| `real_customer_anonymized` | 单个脱敏真实客户场景通过或失败 | 单凭一份文件声明跨客户边界成立 |
| `hypothetical_probe` | 架构探针、待验证假设 | 最终通过或失败 |

单份账目只允许 `reference_baseline`、`single_customer_scenario` 或 `none`。跨客户结论必须在至少两个独立真实场景之间比较业务含义、所有权、纠错生命周期、核心改动和拒绝需求，不能成为单份场景文件的 claim。

同一阶段可以登记多个 `reference_product`。后续参考产品允许停在 `evidence_ready`，用来补充共性、候选差异和未知项，但只有实际测量边界信号并取得验收证据后才能成为最终参考基准。两个参考产品之间的对照不能冒充第二真实客户，也不能由 compare CLI 生成跨客户结论。

## 必需事实

每个非草稿场景明确记录：

1. 要解决的问题、可观察结果和不负责范围；
2. 脱敏来源证据；真实客户最终结果还包含客户确认引用；
3. 每类业务事实的唯一所有者、含义、状态和纠错方式；
4. 启用和未启用的应用；
5. 每项差异在六层中的唯一归属、处置、交付物和证据；
6. 连接器的来源／目标契约、幂等、失败恢复和目标确认；
7. 客户核心分支、客户数据库、共享业务表、客户 migration、跨应用内部读取、现场核心补丁和隐藏强制依赖的数量；
8. 验收证据和仍然成立的限制。

六层固定为 `stable_core`、`configuration`、`policy`、`typed_extension`、`customer_assembly`、`customer_specific`。连接器不是第七层，只能隶属于客户装配或客户专项。

## 状态规则

- `draft` 允许来源证据、验收证据和边界信号尚未补齐，不能被解释为可实施或已通过；
- `evidence_ready` 具备可观察结果、来源、事实、应用和差异，可进入人工业务判断；
- `passed` 需要明确 claim、完整验收证据和全部边界信号为零；
- `failed` 需要明确 claim 和失败证据，保留反证而不是删除场景；
- 脱敏真实客户的最终结果需要客户确认引用；参考产品不允许携带伪造客户确认；
- 已实现策略需要版本、事实输入、输出、纠错和实际运行证据；只有名称或公式设想时保持 `needs_business_evidence`；
- 已实现连接器需要完整契约和失败语义；否则不得出现在 `connectors`。

结构合法与就绪度是两个不同问题：严格 validator 保证 v1 结构与跨字段规则没有被绕过；readiness report 在不改变原文件状态的前提下计算 `draft`、`evidence_ready` 或 `final_ready`。`final_ready` 是形成最终结论前的操作门槛，不是新增的 `assessment_status`，也不等同于客户已经验收。边界信号非零是已经取得的失败证据，不是资料缺口；readiness 必须将其输出为 boundary finding，同时允许完整的 `failed` 场景达到 `final_ready`。

## 用户场景

### 场景 1：录入第二个真实客户草稿

**Given** 已取得允许使用的脱敏业务材料，但部分责任与纠错规则仍需确认  
**When** 操作者从 v1 模板建立 `draft` 账目  
**Then** 未知项保持为空或 `needs_business_evidence`，账目可以校验为合法草稿，但不能标记为通过。

验收条件：草稿不要求客户确认或最终边界计数；校验输出不把草稿描述成产品证据。

### 场景 2：形成单客户最终结论

**Given** 真实客户的事实、生命周期、差异归层、实现和验收证据均已确认  
**When** 操作者把状态设为 `passed` 或 `failed`  
**Then** 校验要求 `single_customer_scenario`、客户确认引用和最终验收证据，并保留全部限制。

验收条件：缺少客户确认、来源证据、事实或验收证据时失败关闭。

### 场景 3：阻止客户专项污染核心

**Given** 场景出现客户核心分支、共享业务表、跨应用内部读取或现场核心补丁  
**When** 账目尝试标记 `passed`  
**Then** 校验拒绝结果，并要求重新归层或接受该场景失败。

验收条件：七项边界信号任一未知或非零时，`passed` 均不可成立。

### 场景 4：阻止空策略和空连接器

**Given** 某项差异被声明为已实现策略或连接器  
**When** 缺少版本化输入／输出／运行证据，或缺少来源／目标契约、幂等、失败恢复和目标确认  
**Then** 校验拒绝该账目。

验收条件：名称、页面公式、SQL、HTTP 200 或空目录均不能成为实现证据。

### 场景 5：把合法草稿转换为可行动缺口

**Given** 第二客户模板在结构上合法，但仍包含占位内容和空证据  
**When** 操作者运行 readiness report  
**Then** 输出逐项区分进入人工业务判断前的缺口和形成最终结果前的客户确认、验收及边界信号缺口。

验收条件：空白模板为 `draft`；参考 OA 为 `final_ready`；真实客户事实完整但尚未最终确认时只能达到 `evidence_ready`。

### 场景 6：保留失败反证

**Given** 真实客户场景的来源、验收、确认和七项边界信号均已完整，但至少一个边界信号非零  
**When** 操作者运行 readiness 和最终 validator  
**Then** readiness 达到 `final_ready` 并输出明确 boundary finding；`passed` 仍被 validator 拒绝，而 `failed` 可以保留该反证。

验收条件：系统不要求把非零信号伪改为零，也不把如实失败误报成“资料尚未准备完成”。

### 场景 7：生成保守的跨场景比较材料

**Given** 参考 OA 和一个 ID 不同的脱敏真实客户场景都已达到 `final_ready`，真实客户结果可以是 `passed` 或 `failed`  
**When** 操作者运行 compare 命令  
**Then** 报告按固定顺序列出启用应用交并差、六层数量、四类处置数量、七项边界值和客户反证，并明确列出人工语义评审义务；报告不得自动宣称跨客户成立。

验收条件：错误证据身份、非最终状态、未就绪或重复场景 ID 失败关闭；同一输入重复运行字节级稳定；`cross_customer_validated` 始终为 `false`。

## 成功标准

- 当前参考 OA 基准以 `reference_product` 身份通过，并明确列出跨客户、真实策略和完整入口限制；
- 第二参考产品 OMS 以 `reference_product / reference_baseline / evidence_ready` 保存，所有尚未测量的生产边界信号保持 `null`；
- 第二客户模板以 `real_customer_anonymized / single_customer_scenario / draft` 身份通过结构校验，但不携带任何“已通过”结论；
- 未知字段、未知版本、错误证据身份、缺客户确认、非零边界信号、未知事实引用、空策略和空连接器均由自动负例拒绝；
- 任何后续真实场景可以通过同一命令重复校验，不需要修改验证器来迁就客户字段。
- 访谈者可以按脱敏工作表采集最小事实，并用 readiness 命令得到确定性的下一步，不会把 schema-valid 草稿误认为证据已齐。
- 最终参考基准与真实客户证据可以生成确定性比较报告，失败反证不会被隐藏，产品边界结论仍由人负责。

## 明确不负责

- 不采集或保存真实客户身份、账号、原始合同、金额或生产文件；
- 不自动判断某项业务差异应属于哪一层；
- 不用 schema 计数替代产品负责人和客户的业务判断；
- 不因模板存在而宣称第二个真实客户场景已经取得或验证。
