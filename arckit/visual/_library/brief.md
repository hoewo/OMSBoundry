# BizFoundry Demo - 视觉基线

## 元信息

- 创建时间：2026-09-25
- 状态：✅ 已接受
- 适用范围：六个独立小系统的本地演示页面

## 定位

这套视觉规则是可用的业务工具基线，不是最终客户品牌。它让六个独立产品拥有一致的阅读层级、操作反馈和演示质量，同时保留每个产品自己的领域术语和数据结构。

页面呈现安静、可靠、克制的运营工作台。它优先帮助用户看懂事实、状态和下一步，不用插画、大面积渐变、装饰性图标或密集卡片制造“完成感”。

## 视觉策略

### 视觉论点

界面像一张整理清楚的业务工作台：深色文字承担主要层级，中性背景划分工作区域，单一冷色只标记可操作位置。边框和留白表达结构，阴影只用于确有前后层级的浮层。

### 内容计划

页面按“产品身份与环境 → 页面用途与下一步 → 当前业务事实 → 状态／历史／帮助”组织。工程信息和技术 ID 保留为可复制的辅助信息，但不压过业务名称、金额、责任人和状态。

### 交互论点

视觉反馈围绕用户动作发生：进入页面时内容轻量显现；可点击行和按钮在 hover／focus 时显示边界变化；提交结果在原操作区域展开。动效只帮助理解状态变化，不承担装饰。

### 品牌气质

专业、清晰、可信、务实。页面不使用营销式口号或虚假的高端感，不让 Demo 看起来像调试控制台。

### 信息层级

1. 页面标题、业务名称和主操作构成第一层；
2. 状态、核心数值和当前任务构成第二层；
3. 说明、时间、revision、来源和诊断信息构成第三层；
4. 危险、错误和阻塞信息使用语义色与文字共同强调。

### 色彩角色

- 冷色强调只用于链接、焦点和主操作；
- 深中性色承载正文与重要数字；
- 浅中性色形成页面背景、分区和悬停；
- 成功、警告、危险和信息色只用于对应语义；
- 状态表达始终同时包含文字，不只依赖颜色。

### 字体节奏

界面使用系统无衬线字体。页面标题采用 28px，区块标题采用 18px，正文采用 15px，辅助信息采用 12–13px。数字与业务名称使用较高字重，长说明保持舒适行高和受控行宽。

### 空间密度

桌面业务页面采用标准偏紧凑密度。页面大区块使用 24–32px 间距，表单与列表行使用 12–16px 间距。密度通过一致节奏建立，不通过把所有内容压进卡片提高信息量。

### 组件性格

- 按钮边界明确，主操作在单个页面区域中保持唯一；
- 表格和列表以对齐、分隔线和状态文字为主；
- 摘要面板只承载确有独立含义的一组事实；
- 表单字段包含持续可见标签、说明和原位错误；
- 卡片不作为默认容器，页面主要依赖区块和分隔线；
- 圆角克制，避免过度胶囊化。

### 状态表达

- hover 使用轻微背景或边框变化；
- focus 使用清晰的 2px 焦点环；
- active 使用短暂位移或色阶变化；
- disabled 降低对比但保持原因可读；
- loading 保留页面上下文，只骨架化数据区域；
- success、warning 和 error 使用语义色、文字和图标三者中的至少两种；
- 提交中、结果显现和帮助展开采用 120–240ms 的短动效，并尊重减少动态效果设置。

### 主题策略

当前只定义高可读浅色主题。暗色主题和客户品牌主题在获得明确依据后覆盖 token 值，不改变信息层级、空间密度或组件行为。

## 参考依据

| 依据 | 使用方式 |
| --- | --- |
| 用户对当前 Demo 的直接反馈 | “简单”必须仍有排版、框架和明确用法，排除裸 JSON 与调试页形态 |
| 现有六应用业务规格 | 领域术语、事实所有权、revision、历史和失败恢复决定页面信息优先级 |
| OMS 交互原型 | 只作为第二参考产品的业务工作区样本，不自动继承其品牌或全部页面结构 |

## 设计原则

1. 先解释再操作：每个页面都说明它处理什么事实和推荐下一步。
2. 业务语言优先：正常路径不要求用户理解 API、容器或数据库。
3. 反馈靠近动作：结果、错误和恢复入口出现在触发区域附近。
4. 历史可见：稳定 ID、revision 和来源能够按需查看和复制。
5. 独立仍完整：每个小系统脱离 Workbench 后仍具有产品身份、导航和帮助。

## 约束

- 目标是桌面浏览器，最低有效宽度为 1024px；窄窗口优先保留关键列并允许横向滚动。
- 使用系统字体和本地资源，不依赖外部字体服务。
- 正文和交互控件满足 WCAG AA 对比度，键盘焦点始终可见。
- 页面不通过隐藏按钮替代服务端授权。
- 最终客户 Logo、品牌色、营销视觉和暗色主题不在当前基线内。
