# 经营承接工作区 - 交互规范

## 交互策略

### 核心任务

用户在一个工作区内选择经营承接记录，确认阶段适用性和承接方式，补齐 Evidence 引用，并核对服务端允许动作、材料缺口、revision 与历史。

### 用户场景

- 经营人员从一个有效 Project 建立承接记录，并判断本阶段适用或不适用。
- 项目经营负责人只处理自己负责 Project 的记录；总经理只能查看状态和历史。
- 操作者选择比选、竞争性谈判或招投标后，按当前策略登记所需材料。
- 岗位、Project Assignment 或直接 Grant 变化后，用户需要明确知道哪些动作已消失。
- revision 冲突、Project／Evidence 暂不可用或引用失效时，用户需要知道没有发生部分写入并可以恢复。

### 主路径

用户通过统一工作台或 Project 上下文进入 → Gateway 使用 IAM Session 签发租户级或 Project 级短期凭证 → 页面读取记录和 `allowed_actions` → 用户确认适用性和方式 → 页面显示材料要求与缺口 → 用户登记 Evidence 引用 → 状态进入 `ready` 或继续显示缺口 → 用户在历史中核对每个 revision。

### 决策点

- 页面只根据 API 返回的 `allowed_actions` 显示动作，不根据“经营经理”“总经理”等岗位名称推断权限。
- Project 级凭证刷新必须携带 Project Scope；由 Project Assignment 产生权限时，还必须携带 Assignment ID 与 revision 作为版本化业务事实。
- `not_applicable` 与“当前方式不要求某份材料”分别显示；空值不代表不适用。
- `ready` 只表示当前材料策略满足，不显示为中标、签约、开票或收款成功。
- 取消是高风险动作；取消后页面保留记录与历史并进入只读状态。
- 401／403 立即退出编辑态；409 重新读取最新 revision；503 保留当前投影与输入并允许使用新的 `command_id` 显式重试；409／422／503 都提供返回原 Project 上下文核对的入口。

### 信息揭示

左侧先显示状态、revision、方式和 Project 引用。右侧先显示当前状态、适用性、材料缺口和服务端允许动作，再按“阶段判断、承接材料、变更历史”逐步展开。技术 ID、来源 revision 和 Capability 保持可见但不压过业务术语。

### 状态流

- 已就绪：显示当前投影、`allowed_actions`、适用性、方式、材料要求和历史入口。
- 建立记录：输入 Project ID 与来源 revision，提交后进入 draft。
- 阶段与材料编辑：只呈现当前权限和状态允许的表单，提交后重新读取详情。
- 提交成功：原位更新状态、缺口、revision 和下一可用动作。
- 权限变化恢复：退出所有编辑态，清除旧动作并通过 Gateway／IAM 刷新。
- 冲突或依赖失败恢复：409 自动读取最新状态；503 保留当前投影和输入上下文，明确失败来源。

### 反馈与恢复

加载和提交反馈固定显示在工作区顶部。提交期间禁止重复操作。成功反馈包含新 revision 和业务结果。401／403 关闭对话框并隐藏写入口；刷新失败时返回统一工作台。409 不重放旧 revision，而是读取最新状态并清除待重试命令。Project 或 Evidence 不可用时，不把失败当作成功，也不清空既有记录；恢复条保留来源 Project 的返回入口，503 只有在用户显式确认后才使用新的 `command_id` 重试原业务意图。

### 输入输出边界

页面只提交 Business Engagement 命令字段，以及 Project／Evidence 的稳定 ID、Version 与 revision。页面不上传文件字节，不编辑 Project，不创建 Contract，不确认 Money 事实。输出包含当前 Engagement、材料要求、缺口、`allowed_actions`、revision 和追加历史。

### 线框投影要求

`default.html` 以独立状态块显示“已就绪”“建立记录”“阶段与材料编辑”“提交成功”“权限变化恢复”“冲突与依赖失败恢复”。每个状态保留 Engagement／Project 身份、当前状态、revision 或明确的尚未建立状态。

## 页面状态

| 状态 | 触发条件 | 关键控件 |
| --- | --- | --- |
| 已就绪 | 列表与详情读取成功 | 记录列表、状态摘要、允许动作、三页签 |
| 建立记录 | 用户拥有 create 并选择新建 | Project ID、来源 revision、确认 |
| 阶段与材料编辑 | 用户选择当前允许动作 | 适用性、方式、材料引用、影响说明 |
| 提交成功 | 命令成功或幂等复用 | 新状态、新 revision、材料缺口 |
| 权限变化恢复 | 刷新后动作变化或收到 401／403 | 只读摘要、刷新权限、返回工作台 |
| 冲突与依赖失败恢复 | 收到 409／422／503 | 失败来源、未写入说明、重新载入或重试 |

## 导航流程

### 进入方式

租户级角色从统一工作台进入。Project 级角色从 Project 上下文进入，地址携带 Project 与 Assignment 事实标识，Gateway 据此向 IAM 请求精确凭证。本地模板环境可以在当前标签页设置测试 Token。

### 页面内导航

左侧记录列表选择 Engagement。右侧“阶段判断、承接材料、变更历史”页签只切换同一记录分区，不改变路由或丢失选中记录。

### 离开方式

用户可返回统一工作台、返回当前记录引用的 Project 上下文或关闭页面。权限刷新失败时提供显式工作台入口；409／422／503 恢复条提供携带 `project_id` 的 Project 返回入口。未提交表单不会静默保存在服务端。

## 交互行为

### 记录列表

- 列表仅显示当前 Credential Scope 内的记录。
- 新建入口只在列表响应包含 `business-engagement.create` 时显示。
- 选中记录后读取详情响应，并用详情级 `allowed_actions` 重绘全部表单。

### 阶段判断

- 设为不适用必须填写原因；恢复适用可以填写说明。
- 只有 `applicability.manage` 显示适用性表单。
- 只有阶段适用且服务端返回 `method.select` 时显示方式表单。

### 承接材料

- 页面同时显示三类稳定材料、是否必需、是否满足和当前 Evidence 摘要。
- 登记或替换要求 File ID、Version 与来源 revision；移除不携带 Evidence 引用。
- 当前方式不要求的材料仍显示“当前方式不要求”，不与阶段不适用合并。

### 权限刷新

- 租户级入口只请求目标 audience。
- Project 级入口请求精确 Project Scope；Assignment 权限同时提交版本化 Project Assignment 事实。
- 刷新后重新读取列表与选中详情；页面不沿用刷新前缓存的写动作。

## 弹窗／对话框

| 名称 | 触发 | 内容 |
| --- | --- | --- |
| 本地访问凭证 | 非 Gateway 环境选择连接 | 当前标签页 Bearer Token |
| 建立经营承接 | 用户拥有 create | Project ID、来源 revision、事实边界说明 |
| 取消确认 | 用户拥有 cancel | 取消影响、原因、确认与返回 |

## 错误处理

| 错误类型 | 展示方式 | 恢复操作 |
| --- | --- | --- |
| 401／403 | 顶部权限恢复条；所有写入口隐藏 | 经 Gateway／IAM 刷新；失败则返回工作台 |
| 409 revision／状态冲突 | 顶部冲突说明和“没有写入”声明 | 清除待重试命令，自动读取最新详情，再由用户重新决定；可返回 Project 核对 |
| 422 引用失效 | 当前动作附近说明 Project／Evidence 引用问题 | 返回携带当前 `project_id` 的 Project 页面核对稳定 ID 与 revision |
| 503 依赖不可用 | 保留当前详情、已填上下文和原业务意图 | 用户显式选择后使用新的 `command_id` 重试，或返回 Project 核对 |
| 无法解析响应 | 页面级错误 | 返回统一工作台或检查入口路由 |

## 加载策略

首次加载保留页面框架和记录区。刷新列表不清空已选详情；详情刷新期间保留业务身份和 revision。提交只锁定当前动作，完成后重新读取详情和列表，确保 `allowed_actions` 与状态同时更新。
