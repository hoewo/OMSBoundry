# 奖金分配工作台交互规范

## 交互策略

### 核心任务

问题 A：C7 已有真实来源 API 和追加式生命周期，但缺少人类可理解、可操作的界面，验证者无法判断来源、策略、权限、纠错关系和失败恢复是否真的可用。

可验证结果 B：用户在一个 Project 范围内建立经营／生产奖金草稿，核对冻结来源、固定策略和人员分配后发布；错误时以同类型新草稿原子替代旧发布事实，或显式撤回；权限、依赖、冲突和金额脱敏均有清楚且不绕过边界的恢复路径。

### 用户场景

1. 经营人员从 Contract 已确认 Settlement 建立经营奖金，选择真实 Person／Assignment，确认金额与分配后发布。
2. 生产人员从 Money 已确认 Receipt Set 建立生产奖金；页面展示其中冻结的 transaction/allocation revision，而不是重新查询当前金额替换历史。
3. 已发布奖池发现来源或参与人错误：用户先建立并核对同类型替代草稿，再执行 supersession；旧新奖池及原因均可追溯。
4. 来源应用暂不可用、引用不匹配或 revision 漂移：页面区分 503／422／409，明确“零部分写入”，恢复后显式重试或重读。
5. IAM 权限变化或金额权限缺失：页面清除旧动作；金额统一显示“金额未授权”，不从旧页面状态泄露。

### 主路径

1. 从 Unified Workbench 经 Gateway／IAM 进入；本地独立验证可在当前标签页输入模板 Token。
2. 输入稳定 Project ID，读取 `/api/v1/bonus-pools?project_id=...`；collection `allowed_actions` 决定是否出现两类“建立草稿”。
3. 选择经营或生产类型，填写 Project／来源 revision 与一个或多个 Person／Assignment 精确引用；固定策略默认 `reference-oa-bonus-v1@1.0.0`、1000 bp、`half_up`。
4. 服务端完整校验真实来源并计算；成功返回草稿，页面重新读取，用户核对来源摘要、digest、策略公式、总额、未分配额与人员分配。
5. `allowed_actions` 允许时以当前 revision 发布；成功后展示 `published` 和追加历史。
6. 后续纠错先建立同类型替代草稿，再从旧 published 奖池发起 supersession；成功后显示 `superseded_by`／`supersedes` 双向关系。

### 决策点

- 经营或生产：决定来源分别是 Contract Settlement 或 Money Receipt Set；不是页面文案差异，而是不同稳定契约。
- 是否发布：必须先核对来源、策略、人员、比例与金额；草稿不是正式事实。
- 替代或撤回：可表达新正确事实时优先替代；业务事实应失效且无替代时撤回。两者都不删除历史。
- 重试或重读：503 在依赖恢复后重试完整输入；409 必须先重读最新 revision；422 必须修正引用或策略，不能原样盲重试。

### 信息揭示

- 列表优先显示奖金类型、状态、revision、Project、来源类型和金额授权状态。
- 详情依次展示：当前状态／动作、金额、冻结来源、固定策略、参与人分配、纠错关系。
- digest、底层 ID 和完整 action 名保持可见，用于第一阶段架构验证；业务演示可在未来增加友好查询，但不能隐藏事实边界。
- 历史按需读取，避免首屏把所有 revision 混成当前事实。

### 状态流

`入口 → 读取中 → 空 Project／已读取 → 建立草稿 → 核对草稿 → published → superseded／withdrawn`

- 草稿建立只在所有真实来源验证成功后出现；依赖失败保持原集合不变。
- published 不提供覆盖编辑；只能进入替代纠错或撤回。
- superseded／withdrawn 只读，保留历史和关系。
- 任何 API 响应都以最新 `allowed_actions` 重新投影；权限变化后不保留旧操作按钮。

### 反馈与恢复

- 成功：说明发生的状态变化和不变量，例如“旧奖池已 superseded，新草稿已 published，历史关联已保留”。
- 401：凭证过期；正式模式回到统一工作台更新会话，本地模式更新当前标签页 Token。
- 403：清空集合动作和详情动作，说明 Project scope 或 Capability 不足；不得显示成 0 条。
- 409：保留输入，要求重新读取最新事实后再决定；不自动覆盖。
- 422：指出需核对 Project／来源／Person／Assignment／策略精确 revision；不建议绕过。
- 503：说明依赖暂不可用且本次零部分写入；恢复后可显式重试完整命令。

### 输入输出边界

- 用户输入稳定 ID、revision、固定策略参数、分配比例和原因；比例合计必须为 10000 bp。
- 服务端负责最终 Project scope、Capability、来源状态、租户、项目归属、人员资格、策略和 revision 校验。
- 页面不直接读其他应用数据库，不接收手填金额，不自行重算成为事实，不保存长期凭证。
- 本轮不实现 D1／联合恢复、C7→Money Payable Suggestion、人员跨项目统计或任意策略编辑器。

### 线框投影要求

`default.html` 必须可见：入口读取、非空列表、真实空状态、建立草稿、核对发布、替代纠错、依赖／冲突恢复、权限／金额脱敏八类状态。

## 页面状态

| 状态 | 触发条件 | 关键控件 |
|---|---|---|
| 入口／读取中 | 首次进入或提交 Project | Project 输入、Progress、状态说明 |
| 已读取 | 返回至少一条奖池 | 类型筛选、奖池列表、详情、动态动作 |
| 空 Project | 读取成功且集合为空 | 真空状态、按权限出现的建立动作 |
| 草稿建立 | 有 calculate + allocation 权限 | 来源表单、参与人行、比例合计 |
| 草稿核对／发布 | draft 且允许 publish | 来源／策略／金额／分配、发布确认 |
| 替代纠错 | published 且允许 supersede | 同类型替代草稿、双 revision、原因 |
| 失败恢复 | 409／422／503 | 重读、修正输入、显式重试 |
| 权限／脱敏 | 401／403 或缺 amount.read | 重新授权、动作收敛、“金额未授权” |

## 导航流程

### 进入方式

- 正式组合：Unified Workbench → Gateway 路由 → C7 根页面；Gateway／IAM 提供受保护会话。
- 本地独立验证：直接打开 C7 根页面，Token 仅保存于 `sessionStorage`。
- 支持 `?project_id=<uuid>&mode=business|production` 预选上下文，不授予任何额外权限。

### 页面内导航

- 左侧在“使用说明／奖池工作区”之间切换。
- 工作区按全部／经营／生产筛选；筛选只改变当前已授权集合的投影。
- 选择奖池后在右侧查看详情；历史为按需加载，不离开工作区。

### 离开方式

- 返回统一工作台或关闭标签页。页面不在 localStorage、Cookie 或服务端保存模板 Token。

## 关键交互

### 建立草稿

- **点击：** collection `allowed_actions` 允许时打开对应类型表单。
- **增加参与人：** 增加一行 Person／Assignment／比例／原因；至少保留一行。
- **提交：** 客户端先校验比例合计，服务端再作完整失败关闭校验；成功重读集合。

### 发布、撤回与替代

- **发布：** 使用当前 pool revision 和原因；成功重读并显示 published。
- **撤回：** 使用当前 revision 和必填原因；成功显示 withdrawn，历史仍可读。
- **替代：** 只列同 Project 当前集合内、同类型、draft 的候选；单请求提交旧新 expected revision 和原因。

### 历史

- **奖池历史：** 读取 `/{pool_id}/history`，显示事件、revision、原因与时间。
- **分配历史：** 有 `bonus-allocation.read` 时读取 allocation history；金额仍受 `amount.read` 控制。

## 弹窗／对话框

| 名称 | 触发 | 内容 |
|---|---|---|
| 访问凭证 | 本地无 Token／用户主动设置 | 当前标签页 Bearer Token 与正式模式说明 |
| 建立奖金草稿 | 对应 calculate 被允许 | Project／来源／策略／参与人精确引用 |
| 替代纠错 | published 且 supersede 被允许 | 替代草稿、双 revision、必填原因和不可覆盖说明 |
| 发布／撤回原因 | 对应动作被允许 | 原因与 expected revision；取消不产生请求 |

## 加载策略

| 场景 | 策略 |
|---|---|
| 首次 Project 读取 | 保留页面骨架并显示明确读取状态 |
| 筛选切换 | 在已读取集合本地投影，不重复请求 |
| 命令成功 | 重新读取整个 Project 集合，避免局部缓存冒充当前事实 |
| 历史 | 用户按需读取；当前事实与历史在视觉上分开 |
| 失败 | 保留用户上下文与可恢复说明；清除未经证明的集合／动作 |
