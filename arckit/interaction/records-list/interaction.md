# 业务记录列表 - 交互规范

## 交互策略

### 核心任务

用户用领域语言浏览、查找和进入当前系统拥有的记录，并从列表发起一个清晰的主操作。

### 用户场景

- 操作者需要继续一条已有演示记录，通过状态、业务名称和更新时间定位目标。
- 评估者需要快速观察系统拥有的记录类型和状态分布，不阅读内部 JSON。
- 操作者首次使用且列表为空，需要知道是生成合成场景还是从空白创建。
- 读取失败时，用户需要知道是当前应用失败还是外部引用失败，并能恢复。

### 主路径

用户从首页进入列表 → 用最少筛选缩小范围 → 选择一条记录 → 进入记录工作区 → 返回后保持筛选和滚动位置。

### 决策点

- 页面只显示能改变工作选择的筛选项，不暴露全部数据库字段。
- 主操作随记录类型固定为“新建合同”“登记资金”“新建人员”等领域动作；Project 列表同时区分普通 Project 和可选 Package。
- 外部引用不可用不自动隐藏记录；列表以明确标记保留当前应用事实。
- 列表级创建入口只按服务端 `allowed_actions` 出现，不从“管理员”“经理”等客户角色名称推断权限。

### 信息揭示

页面标题、记录类型说明、主操作和记录总数优先出现。列表显示名称、稳定业务标识、关键状态、核心业务值和更新时间。技术 ID、revision、来源和异常详情在展开区或工作区显示。

### 状态流

- 加载中：保留标题、筛选和主操作，列表区域显示行占位。
- 内容：显示领域列、状态文字、更新时间和进入详情动作。
- 空状态：解释空的原因并提供一个推荐动作。
- 错误：保留筛选条件，显示失败来源、重试和诊断入口。

### 反馈与恢复

搜索和筛选即时更新结果数量。进入详情后返回保留查询状态。创建成功返回列表时，高亮新记录并显示成功反馈。失败不清空筛选或已有数据。

### 输入输出边界

列表只接受搜索词、预定义状态和有限业务筛选；不允许直接编辑领域事实。它输出记录集合、筛选状态和目标记录导航。

### 线框投影要求

`default.html` 显示“内容”“加载中”“空状态”“错误恢复”“权限变化恢复”五个独立状态。内容状态同时显示领域化列和辅助技术信息的渐进揭示。

## 页面状态

| 状态 | 触发条件 | 关键控件 |
| --- | --- | --- |
| 内容 | 返回至少一条记录 | 筛选栏、主操作、记录表、状态标签 |
| 加载中 | 首次读取或刷新 | 标题、筛选、行占位 |
| 空状态 | 当前筛选无结果或数据库为空 | 原因说明、清除筛选或创建入口 |
| 错误恢复 | 当前应用读取失败 | 失败来源、重试、健康检查 |
| 权限变化恢复 | 刷新后 Capability 改变或签发失败 | 保留列表、隐藏写入口、刷新权限、返回工作台 |

## 导航流程

### 进入方式

用户从 Demo 首页的推荐动作、摘要数字或顶部局部导航进入。

### 页面内导航

点击记录的主要识别区进入记录工作区。点击状态筛选只更新当前列表，不打开新页面。

### 离开方式

返回 Demo 首页，或进入记录工作区。浏览器返回恢复列表查询状态。

## 交互行为

### 搜索与筛选

- 输入搜索词后，系统在短暂防抖后更新列表和结果数量。
- 清除筛选恢复默认集合。
- 活跃筛选始终可见，不把过滤结果误认为完整数据。

### 记录行

- 点击名称或整行主要区域进入记录工作区。
- 键盘焦点按可见顺序移动；状态标签不作为唯一可点击目标。

### 主操作

- 点击主操作进入创建工作区或适用的第一步。
- 无权限时操作不可用并说明所需能力。
- 用户点击“刷新权限”时，经 Gateway 使用当前 IAM Session 重新签发 Project Credential，再重读列表 `allowed_actions`；撤权后的创建入口立即消失。

## 错误处理

| 错误类型 | 展示方式 | 恢复操作 |
| --- | --- | --- |
| 查询失败 | 列表区域错误块 | 保留筛选并重试 |
| 外部引用不可用 | 对应行显示来源不可用 | 仍可进入当前记录；稍后重试 |
| 搜索无结果 | 空结果状态 | 清除筛选 |
| 会话失效 | 页面级身份提示 | 重新登录后恢复当前地址 |
| 权限已变更 | 保留现有列表并退出可编辑状态 | 刷新权限；失败时返回统一工作台 |

## 加载策略

首次加载显示行占位；筛选刷新保留原列表并显示轻量进行状态。分页加载不阻塞已显示记录。返回列表优先恢复本地查询状态，再校验数据是否过期。
