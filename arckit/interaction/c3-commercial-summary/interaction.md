# C3 项目经营链路交互

## 入口与目标

入口位于 Project Workspace 详情的“经营链路”Tab。用户目标是判断当前 Project 的合同、应收／资金、开票事实是否齐备，并能回到事实所有者处理异常。

## 页面规则

- 首次进入 Tab 才加载，不拖慢 Project 基础详情。
- 顶部显示 Project revision、分段数、组合总耗时和观测时间。
- 每个 Resource Link 对应一张卡；卡片顺序不随网络响应顺序变化。
- 卡片固定展示来源应用、关系键、业务状态、linked/source revision 和该来源耗时。
- 金额单位与来源币种一起展示；Contract 未知金额显示“未知（不按 0 计算）”。
- “打开来源”先请求目标应用的人类 Capability，再通过 Gateway 深链导航；服务间 Token 永不进入 DOM。

## 四态

1. 加载：清空旧分段，显示“正在并行读取各来源”。
2. 空：解释需要先建立 Resource Link，不把空列表表达为金额为零。
3. 部分成功：成功卡片正常显示；失败卡片保留位置和稳定状态，页面总通知说明需关注的分段数。
4. 权限变化／整体失败：沿用 Project 的权限恢复面板，退出可编辑状态；不保留旧来源数据冒充当前结果。

## 状态文案

- `available` → 已读取。
- `revision_changed` → 来源已更新。
- `invalid` → 引用已失效。
- `unavailable` → 来源暂不可用。

用户可以“重新读取”；该动作是只读刷新，不改变 Project revision，也不提交来源命令。

## 响应式与可访问性

- 宽屏两列卡片，窄屏单列。
- 状态不仅依赖颜色，同时使用文字标签。
- 来源入口使用可聚焦按钮；卡片中的 `dl/dt/dd` 保持事实标签和数值的语义关系。
