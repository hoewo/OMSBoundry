# 批复审计结果工作区 - 交互规范

## 交互策略

### 核心任务

用户按 Project 范围读取批复／审计当前事实，登记精确来源，查看不可变历史，并通过显式纠正或撤回处理错误；页面不编辑 Project、合同或文件字节。

### 主路径

统一工作台进入 → Gateway／IAM 签发 Results 短期凭证 → 输入 Project ID → 读取项目范围当前结果与 `allowed_actions` → 登记批复 → 以精确批复 revision 登记审计 → 查看历史／纠正／撤回 → 重读当前 revision。

### 决策点

- 新建、纠正、撤回和 Evidence 表单只由服务端 `allowed_actions` 决定，岗位名不进入页面判断。
- `0` 是明确金额；无金额读取能力时金额隐藏／`null`，不能显示为零。
- 更正和撤回使用 `expected_revision`；409 后必须重读，不自动复用旧意图。
- 依赖 503 时明确“本次没有写入”；用户保留上下文，恢复后重试。
- 页面只保存标签页内临时 Token；正式环境使用 HttpOnly 应用凭证。

### 状态流

- 已就绪：Project 当前结果读取成功，结果卡展示类型、状态、revision、来源和动作。
- 空结果：明确尚未登记，不把无权限或依赖失败伪装成空。
- 登记／纠正：对话框要求 Project／来源精确 revision；覆盖金额时要求原因。
- 提交成功：关闭表单并重读当前结果与历史。
- 权限变化：401／403 清除旧写动作，提示重新授权或返回工作台。
- 冲突／依赖失败：409 重读；422 返回来源核对；503 保留输入并等待恢复。

### 输入输出边界

输入只包含 Results 命令、Project／来源／Evidence 稳定引用和外部确认登记值。输出只包含 Results 当前投影、允许动作和不可变历史；Contract、Project 与 Evidence 继续由各自应用拥有。

## 正式装配证据

- D1 Suite Manifest 的正式路由为 `/results`，由统一工作台进入并由 Gateway 向 `approval-audit-results` audience 换取凭证；原生动作命名空间保持 `approval-audit-result`。
- 启用 Results 时页面、路由、容器、数据库、工作负载密钥和备份项共同出现；关闭时页面、路由和容器共同缺席。
- 隔离 D1 已通过页面打开、未选应用 `404`、联合空目标恢复和恢复后复验；真实跨进程登记批复／审计及浏览器动作收敛仍是下一验收项。

## 页面状态

| 状态 | 触发条件 | 关键控件 |
| --- | --- | --- |
| 已就绪 | Project 读取成功 | 结果卡、来源摘要、revision、历史、允许动作 |
| 空结果 | 读取成功且结果集合为空 | 登记入口、批复→审计顺序提示 |
| 编辑提交 | create／correct 能力与合法状态 | 精确来源、金额、Evidence、确认人／时间 |
| 权限变化 | 401／403 或刷新后动作收敛 | 只读摘要、重新授权、返回工作台 |
| 冲突／依赖失败 | 409／422／503 | 零写入说明、重读、来源核对、显式重试 |

## 导航与反馈

左栏在“使用说明／结果登记”间切换，不丢失 Project 上下文。结果卡的历史入口在右侧展示 revision 链；写入成功后同时重读列表、选中结果与历史。提交期间禁用重复发送。每个错误显示 HTTP 类别、是否写入和下一步，不能只显示“失败”。

## 线框投影要求

`default.html` 投影已就绪、空结果、登记／纠正、权限变化和冲突／依赖失败五种状态；关键控件使用 `data-kit` 标注且只使用共享灰度线框样式。
