# Party Directory 主体管理 - 交互规范

## 交互策略

### 核心任务

用户在一个可独立使用的工作区中登记、查找、更正、停用／恢复组织与个人主体，并核对稳定 Party ID、当前 revision 和不可变历史。页面既可作为主体管理产品使用，也可作为其他业务应用选择主体前的管理入口。

### 用户场景

- 主体管理员登记组织或个人，并在重名候选中依靠稳定 ID 与登记标识自行判断；系统不自动合并。
- 业务人员按名称、登记标识、类型和状态查找当前主体。
- 资料发生变化时，操作者基于当前 revision 更正，而不是覆盖历史。
- 不再允许形成新业务引用的主体被停用；既有业务快照和主体历史仍可查看。
- 权限变化、revision 冲突或服务故障后，页面明确说明本次操作没有写入，并提供恢复路径。

### 主路径

用户从统一工作台进入 → Gateway 使用 IAM Session 签发 Party Directory 短期能力凭证 → 页面读取列表和 `allowed_actions` → 用户登记或选择主体 → 详情显示当前档案、revision 和服务端允许动作 → 用户更正或变更状态 → 页面重新读取详情与列表 → 用户在历史中核对每次 revision。

### 决策点

- 列表级登记入口只由列表响应的 `allowed_actions` 控制；详情写动作只由详情响应的 `allowed_actions` 控制。
- `organization`／`individual` 是 Party 类型；客户、甲方、施工方、资质单位等角色不在此页维护。
- 停用不是删除或合并。停用后历史仍可读，只禁止形成新的正式业务引用。
- `409 PARTY_REVISION_CONFLICT` 保留用户输入，同时读取并展示最新 revision；页面不自动覆盖。
- 401／403 立即退出编辑态并刷新能力；数据库或依赖错误不能渲染成空列表或成功。

### 信息揭示

左侧先展示查询、筛选和主体列表。右侧先展示法定名称／姓名、类型、状态、稳定 ID、revision 和登记标识，再按当前权限显示更正、状态与历史动作。技术 ID 与 revision 保持可见，但业务名称仍是首要识别信息。

### 状态流

- 已就绪：列表和选中详情读取成功，动作按服务端能力收敛。
- 空目录：没有符合条件的主体；有创建能力时显示登记入口，否则说明只读范围。
- 登记／编辑：持续显示字段含义、Expected Revision 和不会自动合并的边界。
- 提交成功：原位更新当前投影、revision 和历史入口。
- revision 冲突：保留输入，展示最新事实，要求用户重新决定。
- 权限或服务恢复：隐藏写入口，保留已读取事实，并提供刷新权限或重新载入。

### 输入输出边界

页面只提交 Party 命令字段：Command ID、类型、法定名称／姓名、可选登记标识、Expected Revision、状态和原因。Tenant 与 Actor 来自可信凭证。输出是 Party 当前投影、服务端 `allowed_actions` 和不可变 revision 历史；页面不创建合同、项目角色、登录账号或业务分类。

## 页面状态

| 状态 | 触发条件 | 关键控件 |
| --- | --- | --- |
| 已就绪 | 列表与详情读取成功 | 查询、类型／状态筛选、列表、当前档案、允许动作 |
| 空目录 | 当前过滤条件无记录 | 空状态说明、清除筛选、可选登记入口 |
| 登记／编辑 | 用户具有 create／update | 类型、名称、登记标识、原因、Expected Revision |
| 提交成功 | 命令成功或幂等复用 | 新 revision、业务结果、重新读取后的动作 |
| revision 冲突 | Expected Revision 过期 | 保留输入、最新当前投影、明确重试 |
| 权限／服务恢复 | 401／403／503 或响应不可解析 | 只读摘要、刷新权限、重新载入、返回工作台 |

## 导航流程

### 进入方式

统一工作台在 Suite Manifest 启用 Party Directory 时提供入口。独立开发环境可以设置本标签页模板 Token；正式环境不向浏览器暴露 HttpOnly Capability Cookie。

### 页面内导航

查询和筛选只改变左侧结果集；选择记录更新右侧工作区。查看历史在当前记录内展开，不丢失查询条件。成功写入后保留当前 Party 选择并重新读取服务端事实。

### 离开方式

用户可以返回统一工作台或关闭页面。未提交输入不写入服务端；冲突输入只保留在当前页面，不成为第二份主体事实。

## 交互行为

### 列表与筛选

- 默认查询 active 主体；用户可以显式选择 inactive 或全部状态。
- 查询匹配名称或登记标识，类型与状态筛选共同生效。
- 加载、空结果和错误使用不同状态；错误不能伪装成“没有主体”。
- 列表返回的 `allowed_actions` 决定是否显示“登记主体”。

### 当前档案

- 详情显示 Party ID、kind、status、registration identifier 和 revision。
- 详情级 `allowed_actions` 分别控制更正、状态变化和历史读取。
- inactive 主体显示明确警告，但仍允许按权限查看与重新启用。

### 写入与恢复

- 登记表单不承诺按名称或登记标识去重。
- 更正和状态变化必须携带当前 Expected Revision 与原因。
- 提交期间锁定当前动作，成功后重新读取列表与详情。
- 409 保留输入并读取最新详情；用户确认后使用新 Command ID 和最新 revision 再提交。
- 401／403 隐藏写表单并通过 Gateway 重新授权；重签失败返回工作台。

## 错误处理

| 错误类型 | 展示方式 | 恢复操作 |
| --- | --- | --- |
| 400／422 | 动作附近显示字段或无有效变化说明 | 修正输入后使用新命令提交 |
| 401／403 | 顶部权限恢复条，所有写入口隐藏 | 刷新权限；失败则返回工作台 |
| 409 | 对照显示保留输入与最新 revision，声明零部分写入 | 用户核对后显式重试 |
| 503 | 保留已读列表／详情，标明服务暂不可用 | 重新载入；不得显示空目录或成功 |
| 无法解析响应 | 页面级入口错误 | 返回工作台并检查入口路由 |

## 加载策略

首次加载保留导航、查询和工作区框架。刷新列表不清空已选详情；刷新详情不丢失 Party 身份。历史按需加载。页面不缓存可写主体目录作为离线真相。
