# Billing / Invoice 开票登记工作区 - 交互规范

## 交互策略

### 核心任务

用户在一个可独立使用的工作区中登记现实中已经开出的票据，按权限查看金额，核对 Party／来源快照，管理 Evidence 引用，并通过显式纠正或登记无效保留完整历史。

### 用户场景

- 财务操作人员登记一张已开票事实，并引用两个 Party 的精确 revision 与一个人工或系统来源。
- 经营或管理人员只读查看自己范围内的票据；没有金额能力时仍能看见登记存在，但不能从当前或历史响应推断金额。
- 操作者发现日期、金额或备注录入错误，以当前 revision 和原因追加纠正，而不是覆盖旧记录。
- 操作者登记或替换 Evidence File Version；文件服务不可用时，本次引用命令零写入，现有票据仍可查看。
- 误录或重复登记被标记为“系统登记无效”，但页面不声称现实票据已作废、红冲或退票。
- 能力被撤销、账号停用、revision 过期或依赖暂不可用后，用户能看懂影响并恢复。

### 主路径

用户从统一工作台进入 → Gateway 使用 IAM Session 签发 Billing 短期能力凭证 → 页面读取列表级 `allowed_actions` 与有权汇总 → 用户登记或选择记录 → 详情返回金额收敛后的投影和详情级 `allowed_actions` → 用户纠正、管理 Evidence 或登记无效 → 页面重新读取当前投影、列表和历史。

### 决策点

- “登记已开票”只由列表响应中的 `record` 控制；纠正、文件管理、登记无效与历史分别由详情响应控制。
- 页面不根据“财务”“总经理”等角色名推断动作，也不把隐藏按钮当作授权。
- 缺少金额能力时显示“金额已按权限隐藏”，不能显示零值、占位真实值或从历史泄露。
- `registration_invalidated` 只描述本系统登记；现实票据状态必须由未来明确业务模型承接。
- 409 自动读取最新投影但不自动重放；503 保留输入，并允许以同一 Command ID 安全重试。
- Party、Project、Contract、Settlement、Money Obligation 和 Evidence 都通过稳定 ID／revision 引用；页面不跨应用编辑。

### 信息揭示

左侧先显示筛选、有效金额汇总、记录列表与列表级动作。右侧先显示状态、双方 Party、开票日期、金额可见性和 revision，再分为“登记事实”“票据文件”“变更历史”。稳定 ID、来源 revision 和 Actor 可读但不压过业务名称与状态。

### 状态流

- 已就绪：列表、当前详情和服务端允许动作读取成功。
- 空列表：当前筛选成功但没有记录；有 `record` 时提供登记入口。
- 登记／纠正：持续显示 Party／来源 revision、Expected Revision、原因和边界说明。
- 提交成功：原位刷新当前投影、汇总、revision 和下一允许动作。
- 金额收敛：保留非敏感事实与状态，金额、币种及历史金额均不可见。
- 冲突／依赖失败：409 载入最新事实；422 标明引用错误；503 保留输入与当前投影。
- 权限变化：401／403 退出编辑态并清除旧动作；重新签发失败时返回统一工作台。

### 输入输出边界

页面只提交 Billing 命令字段：Command ID、日期、精确金额最小单位、币种、Party 引用、来源引用、备注、Evidence 引用、Expected Revision 和原因。Tenant、Actor、Capability 与 Scope 来自可信凭证。页面输出 Billing 当前投影、有效汇总、动态允许动作和不可变 revision 历史，不创建应收、回款、核销或税务平台事实。

## 页面状态

| 状态 | 触发条件 | 关键控件 |
| --- | --- | --- |
| 已就绪 | 列表与详情读取成功 | 筛选、金额汇总、记录列表、事实／文件／历史页签 |
| 空列表 | 查询成功且 items 为空 | 空原因、清除筛选、按权限登记 |
| 登记／纠正 | 存在 `record` 或 `correct` | Party／来源 revision、金额、原因、确认 |
| 金额收敛 | 缺少 `amount_read` | 明确隐藏提示、非敏感详情、无金额表单 |
| 提交成功 | 命令成功或幂等重放 | 新 revision、业务结果、重新读取后的动作 |
| 冲突／依赖失败 | 409／422／503 | 零写入说明、最新事实、保留输入、安全重试 |
| 权限变化 | 401／403 或重签失败 | 只读摘要、刷新权限、返回工作台 |

## 导航流程

### 进入方式

Suite Manifest 启用 Billing 且允许显示时，统一工作台显示 `billing-invoice.read` 入口。Gateway 签发 HttpOnly 应用凭证并跳转 `/billing/`。本地开发入口可以在当前标签页保存模板 Token，但不把它持久化到服务器。

### 页面内导航

筛选和记录选择只改变左侧集合与右侧当前投影。事实、文件、历史三个页签始终保留当前登记身份；切换页签不能让选中态消失。写入成功后保持选中登记，并重新读取服务端事实。

### 离开方式

用户可返回统一工作台或关闭页面。未提交输入不写服务端；失败输入仅存在当前页面。C3 组合页面未来只能导航到本工作区完成写操作。

## 交互行为

### 列表与汇总

- 状态和可选 Project ID 构成第一版筛选；Project Scope 下必须显式携带相同 Project ID。
- 列表返回的 `record` 决定创建入口；有效金额汇总只有在 `amount_read` 存在时显示。
- 错误与空结果严格分开；依赖或授权失败不能渲染为零金额或空列表。

### 当前登记

- 详情展示 Party 名称、ID／revision、来源最小快照、Evidence 引用、状态和当前 revision。
- `correct`、`evidence_manage`、`registration_invalidate` 与 `history_read` 分别控制对应区域。
- 无金额能力时纠正表单不呈现金额，也不把金额字段发回服务端。

### 写入与恢复

- 新登记把用户输入的主单位金额确定性转换为最小单位，服务端仍负责最终校验。
- 纠正、Evidence 替换和登记无效必须携带当前 Expected Revision 与原因。
- 409 保留输入并读取最新 revision；操作者重新决定后使用新 Command ID。
- 503 失败不占用成功幂等记录；依赖恢复后使用原 Command ID 重试同一意图。
- 401／403 关闭所有编辑面板、清除旧动作，并通过 Gateway／IAM 刷新。

## 错误处理

| 错误类型 | 展示方式 | 恢复操作 |
| --- | --- | --- |
| 400 | 动作附近显示输入问题 | 修正后重新提交 |
| 401／403 | 顶部权限恢复条，所有写入口隐藏 | 刷新权限；失败则返回工作台 |
| 409 | 说明旧 revision／命令未写入并展示最新投影 | 用户核对后显式重试 |
| 422 | 标明 Party、来源、Evidence 或无有效变化 | 核对稳定 ID／revision 后重试 |
| 503 | 保留已读事实和失败意图 | 依赖恢复后以原命令安全重试 |
| 无法解析响应 | 页面级入口错误 | 返回工作台并检查正式入口 |

## 加载策略

首次加载保留应用身份、筛选与工作区框架。刷新列表不清空已选详情；刷新详情不丢失登记身份。历史按需读取。提交只锁定当前业务动作，不冻结已读取事实和返回工作台入口。
