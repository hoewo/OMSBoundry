# ADR-0003：Contract Ledger 内置最小本地身份

日期：2026-09-19  
状态：接受，用于 Contract Ledger M1-M2；接入外部身份源时重新评审适配边界

## 背景

Contract Ledger 必须能够独立安装和使用。要求客户先部署统一 IAM、OA 或另一个 BizFoundry 系统，会把横向能力重新变成隐藏平台依赖；继续使用进程级 `LOCAL_ACTOR_ID` 又无法证明实际操作者，也不能提供基础只读权限。

## 决策

Contract Ledger 自带窄范围本地身份适配器：

- PostgreSQL 中保存本地用户、BCrypt 密码摘要和服务端会话；
- 空库通过显式环境变量一次性建立首位管理员；
- 固定 `administrator`、`editor`、`viewer` 三类角色；
- 业务 handler 从有效会话构造 `local_user` Actor；
- 每项业务写入和身份管理写入在自身事务内追加不可变审计；
- 外部身份源以后通过相同 Principal/Actor 边界接入，不改变合同事实模型。

本决策不创建共享用户服务。Money Flow Ledger 将来必须根据自己的交付需求实现本地默认身份；只有两个实现稳定后才评估是否共享纯技术原语。

## 安全边界

- 原始密码和原始会话令牌不持久化；
- 服务端授权是唯一可信门禁；
- 用户停用和密码变化通过会话代次立即撤销旧会话；
- Cookie 的 HTTPS `Secure` 标志由部署配置控制，本地 HTTP 必须显式确认非 Secure 模式；
- 认证和授权失败不写成成功业务审计；审计失败则业务事务失败。

## 后果

- 应用增加一个专注本地身份的内部包和 BCrypt 依赖；
- 初次启动需要管理员显式提供 bootstrap 凭据；
- 固定角色不表达客户岗位或复杂数据范围；
- 以后接入 SSO 时仍保留本地用户稳定 ID、Actor 快照和历史审计，不能重写旧操作者；
- 当前不引入网关、集中会话服务、权限 DSL 或跨应用账号同步。

## 重新评审触发条件

- 首个真实客户明确要求 SSO 或多组织数据范围；
- 固定三角色不能满足已验证的通用合同台账职责分离；
- 本地密码运维成本或安全要求超过单体适配器能力；
- Money Flow Ledger 的身份语义稳定且与 Contract Ledger 确认一致。
