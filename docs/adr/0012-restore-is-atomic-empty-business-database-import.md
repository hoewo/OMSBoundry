# ADR-0012：单合同恢复采用空业务库原子导入

日期：2026-09-19  
状态：Accepted

## 背景

CL-M2-009 已提供带精确 SHA-256 的单合同业务账簿，但归档不是 PostgreSQL dump，也不包含身份凭证或 Evidence 文件内容。M2 的可交付性仍要求已经导出的业务数据能够按照明确文档恢复。

直接向任意现有数据库插入会立即引出 Party 合并、业务编号冲突、历史 Command ID 冲突、引用重写和审计归属等尚无客户证据支撑的规则。另一方面，只恢复当前合同字段会丢失不可变 Revision、结算、关闭和审计，不能称为账簿恢复。

单合同归档中的 Relation 只携带另一端登记时快照，并不包含另一份合同的完整历史。Evidence 则只有校验元数据，没有原始字节。这两个缺口必须显式处理，不能用占位数据掩盖。

## 决策

1. 第一版只恢复到“schema 和本地身份已存在，但 Contract 与 Party 均为空”的业务库。
2. 恢复前严格解析 ZIP、校验 manifest、ledger 精确 SHA-256、格式版本、结构和全部本地引用；未知顶层字段不宽松忽略。
3. 含任意 Relation 的单合同归档整体拒绝。不得伪造对端合同、放松外键或静默遗漏关系。
4. 恢复完整的 Contract 当前投影、Party／link、取消、Instrument、Revision／Snapshot、Settlement、Closure、Evidence 元数据和源 Contract 审计。
5. 对维持正式事实与后续幂等不变量所需的命令记录，从归档中已有的不可变事实和类型化审计确定性重建；不反向猜测未导出的草稿编辑请求负载。
6. Evidence Version 增加 `available`／`missing` 内容状态。恢复的源 Version 为 `missing`，不分配虚假 storage key；页面和下载端点必须如实拒绝缺失内容。
7. 恢复操作由独立 Restore Command ID 和 ledger SHA-256 幂等识别；相同归档不会重复插入或重复审计。
8. 使用数据库级恢复互斥锁和单一事务提交全部业务事实、源审计、恢复记录与 `contract_ledger_restored` 审计。
9. `business.restore` 仅授予 administrator；当前管理员只作为恢复行为 Actor，不替换源历史 Actor。
10. 本功能不恢复用户／会话，不连接 Money Flow，不执行覆盖、合并、批量或 Evidence 字节恢复。

## 原因

- 空业务库边界让 ID、业务编号和 Party 语义保持原样，避免未经定义的合并策略破坏历史。
- 先做严格预检、再做原子写入，能够把坏归档与数据库中途失败都收敛为“零部分事实”。
- 保留源 Actor 并追加本地恢复 Actor，可以区分“原来发生的业务行为”和“本次运维恢复行为”。
- Evidence `missing` 状态让校验元数据仍可用，又不会生成指向不存在文件的虚假下载链接。
- Relation 拒绝比占位或丢弃更安全；多合同依赖恢复需要单独定义闭包、顺序和跨归档冲突。

## 后果

- 第一版不能把某份合同导入已有业务库，也不能恢复含 Relation 的归档；这两项仍是明确开放能力，而不是隐式失败。
- 业务数据可恢复不等于完成灾难恢复。Evidence 原始字节、数据库级备份、部署配置和恢复演练仍需后续交付说明。
- 恢复后的 Evidence 旧 Version 只能查看元数据；追加新 Version 不会补齐旧文件。按 SHA-256 重新挂接原内容需要独立能力。
- 源归档中未包含完整负载的历史草稿编辑命令不会被猜测重建，但其审计仍保留；正式不可变事实及其命令链必须完整恢复。
- 重新导出的账簿会多出恢复审计，并把 Evidence 内容状态标为不可用，因此与源 ledger 的字节摘要不同；验收使用语义比较而不是错误地要求 ZIP 二进制相同。

## 被否决方案

### 覆盖现有同 ID 合同

会绕过不可变历史、破坏现有引用，并把恢复变成无审计的管理员更新能力。

### 自动合并 Party 与合同编号

同名主体、相同登记标识和相同合同编号是否代表同一业务身份没有通用答案；第一版没有足够证据制定安全合并规则。

### 为 Relation 创建占位合同

单个 revision 快照不足以构造对端合同的正式历史。占位会制造看似真实但不可重放的合同事实。

### 丢弃 Evidence 或生成虚假 storage key

丢弃会失去文件校验依据；虚假 key 会让页面提供必然失败或可能错误命中的下载。显式 `missing` 才能保持真实性。

### 尽力恢复可以插入的行

部分恢复会让 revision、结算、关闭、Evidence 和审计相互矛盾，后续很难判断哪些事实可信，因此必须全事务成功或全回滚。
