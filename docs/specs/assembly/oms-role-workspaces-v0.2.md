# OMS 四工作区信息架构 v0.2

日期：2026-10-11
状态：已接受的本地验证原型；不是正式 OMS 产品规格

## 1. 问题 A → 可验证结果 B

问题 A：两个一级入口虽然清晰，但老板、事项经办人与财务人员的工作目标不同；若所有发票、应收、回款、应付和付款都只能先进入单个事项查看，财务跨事项工作路径过深。若把每个动作都铺成侧栏菜单，又会拆散同一经营事项并增加学习成本。

可验证结果 B：本地 Demo 固定使用四个一级工作区——经营总览、经营事项、收付台账、待办事项——分别承载整体判断、事项闭环、跨事项专业处理和行动队列。四个工作区只投影同一批演示事实，不复制业务记录，不改变现有 Owner 和系统边界。

## 2. 工作区职责

1. **经营总览**：面向老板和管理者，只展示整体合同、应收、回款、付款、风险敞口、事项列表和需要介入的例外；
2. **经营事项**：面向经营负责人和经办人员，页面内提供事项列表、经营全貌、合同与资料、协作方与人员、履约与结算五个二级工作区；经营全貌先用“合同边界 → 履约／计量 → 收付循环”说明业务阶段，再保持单事项的上游履约收款、下游履约付款、经营台账和闭环条件；
3. **收付台账**：面向财务，页面内先分上游收款／下游付款，再提供发票管理、应收管理、回款记录和结算管理、应付管理、付款条件、付款授权、支付记录等二级筛选，支持事项和状态筛选，并能返回事项上下文；
4. **待办事项**：面向实际处理人，按经营影响排列逾期回款、付款判断和资料补齐，直接进入对应事实或处理入口。

## 3. 信息模型原则

- “与经营事项相关”不等于“只能从经营事项进入”；同一事实允许有事项投影和专业台账投影；
- 经营事项是界面聚合上下文，不拥有合同、资金、主体、人员、文件或授权事实；
- Contract Ledger、Money Flow Ledger、Party Directory、People & Groups、Evidence Service 和 IAM 的数据所有权保持不变；
- 发票、应收、回款、结算、应付、付款判断、授权和实付仍是分别登记的事实；任何界面相邻关系都不得表示自动生成或自动流转；
- 合同价款、已确认变更后的当前价款、履约、计量、验收、开票、应收和回款不得压成一个“项目进度”；行业资料只证明这些是常见候选节点，客户是否采用、采用何种名称和触发条件仍需真实合同与经办人确认；
- 每个下游协作关系至少要能表达候选主体类型、承接范围、合同或其他依据、资质／名册材料和付款路径判断；企业、班组或个人类型不得自动决定付款对象或流程；
- 跨事项台账必须保留事项／合同、往来对象、状态和日期等筛选字段；点击记录可以回到事项，但不得生成第二份记录；
- “收付台账”是经营资金专业工作区，不冒充法定会计账簿或总账系统。

## 4. 交互与层级

- 桌面侧栏固定四个入口，不展开成业务动作树；手机底部固定四个入口；
- 经营事项和收付台账的二级入口固定显示在当前页面顶部，不隐藏在“更多”菜单，也不升级成全局侧栏树；
- 经营事项二级入口用于切换同一事项语境下的工作面；收付台账二级入口用于筛选跨事项同类事实，两者不得复制记录；
- “人员款项”“智能材料”等参考原型模块在缺少本项目事实前不进入固定导航；
- 主要工作在三层内完成：一级工作区 → 页面内二级工作面 → 事项／记录／待办；
- 经营总览可以进入事项或待办；收付台账可以按方向、业务类型、事项和状态筛选，并打开依据详情；待办可以直接打开对应业务事实；
- 页面不使用重复中英文眉题、装饰性副标题或多余卡片证明产品完整性。

## 5. 验收

- 默认进入经营事项，四个桌面入口和四个手机入口可切换且面包屑同步；
- 经营事项五个二级入口均可切换，分别显示两件事项、单事项经营全貌、合同资料、两类协作关系及履约结算；
- 经营全貌固定显示合同边界、履约／计量和收付循环三个主阶段；履约依据缺失可直接打开详情，且不会自动改变开票、应收或回款记录；
- 经营总览显示 5 项汇总、2 件事项和 3 项需要介入的例外；
- 收付台账可在上游／下游间切换，上游显示发票管理／应收管理／回款记录，下游显示结算管理／应付管理／付款条件／付款授权／支付记录；付款条件和付款授权可分别筛出不同状态；
- 事项和状态筛选共同生效，风险筛选可以缩小到对应记录；
- 待办的三个动作均可打开对应详情；
- 1280 桌面和 390×844 手机无整页横向溢出，宽台账只在自身容器滚动；
- 页面脚本语法、浏览器 console warning／error 和旧单事项交互均保持正常。

## 6. 不负责范围

本版本不确认正式角色权限、岗位首页、会计科目、票税规则、付款条件、审批授权规则、跨合同资金分配、正式 API、数据库、IAM Grant、持久化、真实文件或部署。示例数据和角色路径只用于验证信息架构，不得描述为客户已经确认的正式 OMS。
