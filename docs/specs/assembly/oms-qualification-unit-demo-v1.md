# OMS 资质单位参考 Demo v1

日期：2026-10-08  
状态：已接受的界面参考切片；不是正式 OMS 产品规格

## 1. 问题 A → 可验证结果 B

问题 A：现有 OMS 只有一套未经过产品确认的演示实现，但已经确认它位于 OA 业务链中的“资质单位”主体视角，团队需要先看到一个可以讨论的信息架构和交互版本。  
可验证结果 B：在现有 OA 统一工作台内提供一个只读、可交互、明确标注演示数据的资质单位经营桌面，并从 `oatest` 的 `/oms/` 入口访问；它不得写入或冒充 Contract、Money、People、Party、Project、IAM 等应用的真实事实。

## 2. M0 视角

当前视角固定为：

`甲方单位 → 资质单位（当前主体） → 协作方（下游角色待确认）`

“资质单位”是本切片唯一确认的产品事实。甲方、协作方、施工队、项目组、承包方等具体业务角色和正式命名仍需后续访谈与真实流程证据确认。

## 3. 页面结构

Demo 由五个只读工作区组成：

1. 运营总览：合同组合、未来 30 天资金脉搏和经营例外；
2. 合同经营：上游甲方合同与下游协作合同的并列查看和状态筛选；
3. 收付计划：应收、应付和支付条件的演示队列；
4. 协作资源：协作队显示语、名册风险和关联经营信息；
5. 经营待办：按影响排序的例外事项。

交互包括工作区切换、合同状态筛选、详情抽屉、待办抽屉、工作区跳转和样例刷新提示。所有交互只改变浏览器内的展示状态。

## 4. 所有权与不变量

- Workbench 只组织界面，不成为业务事实所有者；
- Contract Ledger 仍拥有合同、结算及其不可变历史；
- Money Flow Ledger 仍拥有确认义务、实际收付、核销和余额；
- People & Groups 仍拥有人、Group、Membership 和名册快照；“协作队”只是客户界面显示语；
- Party Directory 仍拥有主体当前档案、稳定 ID 和 revision；
- IAM 仍拥有身份和能力授权；本 Demo 不创建或绕过 Grant；
- 合同金额不自动生成应收或应付，预计日期不自动生成实际收付；
- 页面不得调用真实业务命令、写入数据库或把示例状态描述成真实经营结论；
- 所有金额都是带单位的展示字符串，不进入计算或持久化，因此不引入二进制浮点金额事实。

## 5. 入口与装配

- 公网入口：`GET /oms` 或 `GET /oms/`；
- Gateway 返回 `303 See Other` 到 `/workbench/?preview=oa&view=oms-reference`；
- 页面仍经过 `Browser → Nginx → Gateway → Unified Workbench`，不增加 Nginx 直连或新的业务服务；
- Workbench 的 `preview=oa` 模式不读取受保护投影，页面显著显示“演示数据／不读取或写入真实业务”；
- `/oms/` 是装配别名，不是新的数据所有者、应用数据库或永久路由契约。

## 6. 来源与适配原则

信息结构参考独立 OMS 原型仓库提交 `27c614838fe1`。该原型没有经过正式产品确认，因此本切片只复用可讨论的信息分组和样例语义，并按 BizFoundry 当前所有权边界重新表达；不复制其前端技术栈、不把假数据模型升级成正式 API，也不把十个原型工作区视为已确认产品范围。

## 7. 验收

- Gateway 对 `/oms`、`/oms/` 的 GET／HEAD 均返回固定 303，其他方法不获得该演示入口；
- Workbench 页面包含资质单位视角、来源提交、演示边界、五个工作区和 Owner 提示；
- CSS、JavaScript 独立提供并通过内容类型检查；
- 桌面和 390 像素手机视口无横向溢出；
- 合同筛选能把 5 条缩为 2 条，详情抽屉可打开，收付工作区可切换；
- Gateway、Workbench 单元测试与 vet 通过；
- D1 只替换 Gateway 和 Workbench，17 个容器全部健康，其余 15 个容器 ID 不变；
- 公网 `/oms/` 跳转、页面和静态资源返回符合预期。
