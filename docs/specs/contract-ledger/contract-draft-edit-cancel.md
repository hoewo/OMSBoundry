# Contract Ledger：合同草稿编辑与取消

里程碑：M1  
功能编号：CL-M1-004  
状态：已接受

## 目标

用户能够在合同激活前修改草稿基本字段，或在决定不再签署时取消草稿。编辑与取消都必须具备命令幂等、Expected Draft Version 并发检查和可追溯的命令记录。

## 可编辑字段

编辑命令使用完整字段替换，包含：

- 编号命名空间；
- 合同编号；
- 标题；
- 通用分类；
- 币种；
- 可选合同总额；
- 可选签署日期；
- 可选生效日期。

字段校验、金额精度、币种规范化、日期规则和编号唯一范围与创建草稿完全一致。

以下内容不可通过编辑命令修改：

- Contract ID；
- 创建 Command ID；
- 创建时间；
- 生命周期状态；
- Current Revision；
- 签约主体关联；
- 已完成命令历史。

## 编辑规则

- 只有 `draft` 状态可以编辑；
- Expected Draft Version 必须等于数据库当前版本；
- 成功编辑后 `draft_version` 加一；
- 如果标准化后的全部字段与当前草稿完全相同，拒绝为“草稿内容没有变化”，不记录命令也不增加版本；
- 修改编号时继续执行当前账簿内“编号命名空间 + 合同编号”不区分大小写的唯一约束；
- 编辑合同基本字段不会改写或移除签约主体关联。

## 取消规则

- 只有 `draft` 状态可以取消；
- 取消原因必填，去除首尾空白后长度为 1 至 500 个字符；
- Expected Draft Version 必须等于数据库当前版本；
- 成功取消后状态变为 `cancelled`，`draft_version` 加一，Current Revision 仍为空；
- 取消命令的原因和发生时间保存在不可变命令记录中；
- 取消不物理删除合同、签约主体关联或以前的草稿命令；
- `cancelled` 合同仍可查询，但不能编辑、增删签约主体或激活；
- 当前版本不提供恢复草稿或撤销取消。

## 幂等规则

- 编辑与取消命令共享本功能内的 Command ID 唯一空间；
- 相同 Command ID 和相同标准化负载重放时，返回第一次结果，不再次增加版本；
- 相同 Command ID 改变字段、原因、Expected Draft Version 或跨编辑/取消动作复用时，返回幂等冲突；
- 幂等重放优先于状态和版本检查，因此成功取消或编辑的原命令在后续状态变化后仍可安全重放。

## 用户流程

```text
打开合同草稿详情
  ├─ 修改完整基本字段
  │    → 提交 Command ID + Expected Draft Version
  │    → 事务内检查幂等、状态、版本、编号和实际变化
  │    → 保存字段并使 draft_version + 1
  └─ 填写取消原因
       → 提交 Command ID + Expected Draft Version
       → 事务内检查幂等、状态和版本
       → 状态改为 cancelled，draft_version + 1
```

## 验收标准

- 能编辑全部允许的基本字段，并保持精确金额；
- 编辑不改变 Contract ID、创建 Command ID、创建时间和签约主体关联；
- 无变化提交被拒绝且不增加版本；
- 修改为重复编号时返回冲突且不改变原草稿；
- 能用必填原因取消草稿；
- 取消后合同仍可查询并显示原因、时间和签约主体；
- 取消后不能编辑、增删签约主体或再次以新命令取消；
- 编辑和取消均支持安全幂等重放；
- 复用 Command ID 但改变负载或动作时明确拒绝；
- 过期 Expected Draft Version 被拒绝且不改变草稿；
- 页面具备 CSRF 防护和请求大小限制；
- 真实 PostgreSQL 集成测试验证事务、约束、版本和测试数据清理；
- 不依赖 Money Flow、Project、Approval 或外部主体中心。

## 本功能不包含

- 编辑主体目录资料；
- 批量编辑；
- 恢复已取消草稿；
- 激活、签约主体快照或正式 revision；
- Actor、权限和完整审计事件；
- 文件、证据、审批和电子签章；
- 应收应付或其他跨系统业务流动。
