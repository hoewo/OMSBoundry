# Contract Ledger 最小本地身份、权限与写入审计

功能编号：CL-M1-006  
日期：2026-09-19  
状态：已实现并验证

## 目标

Contract Ledger 在不依赖客户 SSO、OA、统一 IAM 或另一个 BizFoundry 应用的情况下，能够从空数据库建立首位管理员，并以本地用户、密码和服务端会话完成最小身份认证。所有业务写入都必须从已认证会话取得可信操作者，经过固定权限判断，并与不可变审计记录在同一个 PostgreSQL 事务中提交。

本功能是 Contract Ledger 自身的默认身份适配器，不是多个系统共用的权限平台。

## 本地用户

本地用户包含：

- 稳定 UUID；
- 不区分大小写的唯一用户名；
- 显示名称；
- BCrypt 密码摘要；
- 固定角色 `administrator`、`editor` 或 `viewer`；
- `active` 或 `disabled` 状态；
- 会话代次、创建时间、更新时间和密码更新时间。

约束：

- 不保存、展示或记录明文密码；
- 用户不物理删除；
- 用户名标准化后不可修改；
- 密码长度为 12 至 72 字节；
- 不开放自助注册；
- 管理员可以创建用户、调整角色、停用或启用用户、重置密码；
- 用户可以修改自己的密码；
- 当前用户不能停用自己，也不能移除最后一名有效管理员；
- 密码变化或用户停用会使该用户已有会话全部失效。

## 首位管理员

当数据库中没有本地用户时，应用启动必须同时取得：

- `BOOTSTRAP_ADMIN_USERNAME`；
- `BOOTSTRAP_ADMIN_PASSWORD`；
- 可选 `BOOTSTRAP_ADMIN_DISPLAY_NAME`。

应用在数据库事务中创建唯一首位管理员和审计记录。若数据库已有任何用户，启动变量不会修改既有用户或密码。只提供一半凭据、密码不合规或空库未提供凭据时，应用拒绝启动并返回明确错误。

## 会话安全

- 登录成功后生成至少 256 bit 密码学随机令牌；
- 浏览器只持有原始令牌，数据库只保存 SHA-256 摘要；
- Cookie 使用 `HttpOnly`、`SameSite=Lax`、固定 `Path=/`，不设置 `Domain`；
- `SESSION_COOKIE_SECURE` 控制 HTTPS 环境的 `Secure` 标志，本地 HTTP 验收显式设为 `false`；
- 会话采用可配置的绝对有效期，默认 12 小时；
- 注销在服务端撤销会话并清除 Cookie；
- 过期、撤销、代次不符、用户停用或不存在的会话都视为未登录；
- 登录失败统一返回同一错误，不泄露用户名是否存在；
- 连续 5 次错误密码使已存在账号锁定 15 分钟，成功登录后清零；
- 登录表单和所有写表单继续执行 CSRF 校验与请求大小限制。

健康检查不要求登录。除登录页和健康检查外，所有页面与业务接口都要求有效会话。

## 固定权限

| 动作 | administrator | editor | viewer |
| --- | --- | --- | --- |
| 查看首页、主体、合同和审计 | 允许 | 允许 | 允许 |
| 创建主体 | 允许 | 允许 | 拒绝 |
| 创建、编辑、取消合同草稿 | 允许 | 允许 | 拒绝 |
| 添加、移除签约主体 | 允许 | 允许 | 拒绝 |
| 激活合同 | 允许 | 允许 | 拒绝 |
| 管理本地用户 | 允许 | 拒绝 | 拒绝 |
| 修改自己的密码 | 允许 | 允许 | 允许 |

服务端必须执行权限判断；隐藏按钮只改善界面，不构成授权控制。权限拒绝返回 `403`，不得调用领域写用例，也不得生成成功业务审计。

## 可信 Actor

业务写入 Actor 只能由服务端根据当前会话构造：

```text
kind = local_user
id = local_users.id
display_name = 执行时显示名称快照
```

HTTP 表单、URL、请求头或业务字段不得覆盖 Actor。领域写输入必须显式携带 Actor，repository 在事务内保存它。

## 写入审计

新增应用内不可变审计账簿，至少记录：

- 审计 UUID；
- 对象类型和对象 UUID；
- 动作；
- 可用时记录原命令 UUID；
- Actor 类型、ID 和显示名称快照；
- 发生时间；
- 最小结构化结果，例如草稿版本、revision、角色或目标用户角色。

必须覆盖：

- `party_created`；
- `contract_draft_created`；
- `contract_draft_updated`；
- `contract_draft_cancelled`；
- `contract_draft_party_added`；
- `contract_draft_party_removed`；
- `contract_activated`；
- `local_user_bootstrapped`；
- `local_user_created`；
- `local_user_role_changed`；
- `local_user_status_changed`；
- `local_user_password_changed`；
- `local_user_password_reset`。

审计表禁止 `UPDATE` 和 `DELETE`。业务写入与对应审计必须处于同一事务：审计写入失败时业务事实、命令、版本变化和身份变化全部回滚；幂等业务命令重放不新增审计。

迁移前已有命令投影到新审计账簿时：

- 已存在的激活 Actor 原样保留；
- 其他历史写入使用 `legacy_unknown:actor-not-recorded-before-cl-m1-006`；
- 不从时间、终端环境或当前用户猜测历史操作者；
- 投影只索引既有事实，不修改原命令和业务事实。

## 界面

- 未登录访问业务页面跳转到登录页，并保留站内安全返回地址；
- 页面显示当前用户、角色、注销和修改密码入口；
- 管理员拥有本地用户管理页；
- viewer 不渲染业务写表单；
- editor 不渲染用户管理入口；
- 合同详情显示完整合同写入审计时间线；
- 提供只读的全局审计列表，供三类已认证用户查看。

## 明确不做

- 外部 SSO、LDAP、OAuth、OIDC 或客户 OA 集成；
- 多组织、数据行级范围和可配置权限设计器；
- 自助注册、邮件找回密码和多因素认证；
- 跨 Contract Ledger 与 Money Flow Ledger 的统一账号；
- 登录成功/失败的长期安全分析平台；
- 把角色名称替换成客户岗位。

## 验收标准

1. 空数据库缺少 bootstrap 凭据时拒绝启动；提供合规凭据后只创建一个管理员，重复启动不改密码、不重复审计。
2. 数据库不出现明文密码或原始会话令牌；Cookie 属性和会话过期符合规格。
3. 登录错误信息不区分用户不存在与密码错误；第 5 次错误后账号锁定，锁定期满可登录。
4. administrator、editor、viewer 的页面和直接 HTTP 权限与权限表一致。
5. 所有业务 use case 收到的 Actor 来自当前会话，伪造 Actor 输入无效。
6. 新的七类业务写入各产生一条不可变审计，幂等重放不重复产生。
7. 历史命令投影数量正确，未知 Actor 明确标记而不伪造；原有激活 Actor 保留。
8. 故意制造审计写入失败时，业务写入或身份变更完全回滚。
9. 停用用户、修改或重置密码后，其旧会话立即失效。
10. 不能停用当前用户或移除最后一名有效管理员。
11. Money Flow 数据库和应用停止时，本功能仍可完整运行。
