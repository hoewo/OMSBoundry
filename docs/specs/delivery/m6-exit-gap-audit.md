# M6 可交付性退出缺口审计

里程碑：M6  
功能编号：M6-006  
日期：2026-09-20  
状态：已完成审计

## 1. 目标

逐条核对开发计划中的 M6 验证内容和退出门槛，防止已经完成的交付验证被重复建设，也防止缺少客户事实的性能、导入、权限或装配事项被强行实现。每一项只接受当前规格、实际 release 验收和已运行测试作为直接证据。

状态含义：

- `通过`：已有直接、可重复的工程证据；
- `部分通过`：稳定边界已证明，但更大的使用范围尚无事实；
- `外部待验`：必须取得客户样例、容量目标或新参与者，当前不能由工程自证；
- `不适用`：对应可选能力尚未存在，不能制造对象来测试。

## 4. 当前可以立即补齐的最小缺口

审计当时确定的下一个安全切片为 `M6-007`：**双 Release 同主机运行手册与操作复演**。该切片随后已经完成并验证。

理由：

1. M6-004 已经证明实际产物能同时运行，输入和故障边界不是猜测；
2. 当前只有单应用安装／升级、备份／恢复手册和面向测试的组合验收命令，缺少操作者视角的组合运行顺序；
3. 该切片不需要修改业务 schema、领域代码、身份模型或创建连接器；
4. 可以明确两个数据库、Evidence、端口、Cookie、进程、备份和恢复永远分别拥有，避免商务组合重新制造共享平台；
5. 完成后可用现有 actual bundle 做一次按手册复演，形成直接证据。

`M6-007` 至少应覆盖：前置条件、目录和端口规划、两个 release 独立校验与迁移、首次启动、ready、浏览器双登录、独立停启、分别备份、单侧恢复、故障定位、明确禁止项和卸载／数据保留边界。

## 5. 当前不能安全实现的事项

- 不在没有数据规模、硬件和 SLO 时设立任意性能“通过线”；
- 不在没有真实 Excel 样例和纠错语义时开发通用导入；
- 不在没有第二用户和组织授权需求时扩展 Money Flow 身份模型；
- 不为故障注入而创建空连接器、消息队列或外部对象存储；
- 不把三类参考装配场景变成演示数据后声称客户验收；
- 不把“新开发者可复现”改写成自动化测试已经代表真人操作。

## 6. 结果

M6 的核心产物安装、升级、恢复和同机故障隔离已有直接证据；本审计识别出的组合运行手册缺口随后由 `M6-007` 完成。至此仓库内可验证范围已收口，其余事项必须等待容量目标、客户样例、真实用户、真实操作者或真实业务流，不以无事实代码追求形式上的里程碑关闭。
