# OMS1 用户开通与组织管理 V1

日期：2026-10-27
状态：BF-272 账号激活、BF-275 用户级别／系统管理页／组织创建、BF-276 既有用户管理员挂载、BF-277 组织显示名称设置均已发布；单组织限制已由 BF-294 发布取代；组织内新增用户交互已由 BF-297 发布取代

## 1. 问题与结果

> 系统把 IAM 用户误称为“成员”，又缺少平台级组织管理入口 → 明确用户与成员是两个对象：IAM 管理系统管理员、管理员和普通用户；People & Groups 管理成员、职位、部门、业务角色与职责；仅系统管理员可以从独立页面创建组织。

## 2. 对象边界

- **用户（IAM Subject）**：能够登录和使用系统的人，拥有账号标识、密码、状态、Session 和用户级别。
- **成员（People Person）**：公司业务人员档案，拥有部门、职位、业务角色、入离职状态及业务职责。
- 用户和成员可以通过同 Tenant 内的稳定引用关联，但二者允许独立存在；不得共享密码、账号状态、管理员标记、职位或业务角色字段。
- 用户级别只有：`system_administrator`（系统管理员）、`administrator`（管理员）、普通用户。
- 财务、经营、工资等权限是独立 Capability，不是用户级别；未来的“财务负责人”等也不能扩成第四种用户级别。

## 3. 系统管理员与组织创建

1. 系统管理员登录后只进入独立系统管理页，不直接进入组织业务工作台。
2. 系统管理页展示当前服务器全部组织的稳定 ID、名称、状态、用户数量、管理员数量、创建时间和必要运维状态，不展示工资、财务、项目等业务事实。
3. 只有系统管理员可点击“创建组织”；登录页不提供公开创建入口。
4. 创建时填写组织名称、首位管理员姓名及手机号或邮箱。
5. IAM 在单一事务中建立 Tenant、首位 `pending` 管理员用户、24 小时一次性激活 Token 与不可变审计；任一步失败不得留下半个组织。
6. 系统管理员复制激活链接并通过可信渠道交给首位管理员；本人设置密码后激活。
7. BF-294 起，一个全局登录账号可拥有多个组织 Subject；已激活账号加入新组织不重复设置密码，登录后可显式切换组织。详见 [`multi-organization-account-membership-v1.md`](./multi-organization-account-membership-v1.md)。

## 4. 组织用户新增与激活

1. 管理员在“账号与租户”页面点击“创建邀请链接”，只选择加入后的“普通用户”或“管理员”；不得代填受邀人姓名、手机号、邮箱或密码。
2. IAM 建立不可登录的 `pending` 占位 Subject，并返回 24 小时一次性邀请链接。链接只固定 Tenant、用户级别、有效期和随机凭证。
3. Workbench 只在本次结果显示完整链接并提供复制；没有短信或邮件提供商时不得显示“已发送”。Token 放在 URL fragment，页面通过 JSON 请求体预览／提交，不进入查询串。
4. 本人打开链接后看到组织名称、加入级别和有效期，自行填写姓名，选择手机号或邮箱，并输入 12～72 字节密码。
5. 登录账号不存在时，IAM 在一个事务中把占位账号转为真实全局账号、激活当前 Tenant Subject、消费 Token 并写不可变审计。
6. 登录账号已存在时，输入内容解释为原密码；只有原密码正确、账号启用且尚未加入当前 Tenant 时，IAM 才把占位 Subject 原子关联到原全局账号。不得更新原密码或复制其他 Tenant 权限。
7. 完成后本人使用手机号或邮箱和本人密码登录。成员关联不在邀请中预设，注册完成后由本组织管理员通过 People 端口显式处理。

## 4.1 组织设置

- 管理员可以在“账号与租户”页面修改当前组织的显示名称。
- 名称为 1～100 个字符；组织稳定 ID、创建时间、账号归属和业务引用不可修改。
- 改名按当前可信 Session 的 Tenant 限定并写 IAM 审计；同名重复保存不重复写审计。
- 普通用户只能查看所属组织，不能修改；系统管理员继续在隔离系统管理页工作，不能借此进入组织业务面。
- 这里的名称只服务登录与工作台显示。营业执照名称、统一社会信用代码、法定代表人等企业主体资料归 Party Directory，不在 IAM Tenant 保存。

## 4.2 账号与成员资料维护

- 管理员可从账号目录修改当前组织 Subject 的账号姓名；请求必须包含 expected revision，修改写 IAM 审计，登录标识和其他组织 Subject 不变。
- 已关联员工的姓名、部门和岗位由 People Person 拥有，账号目录只提供独立的 People 编辑入口；不能把两次命令包装成一次跨库原子更新，也不能按姓名自动同步。
- 登录或组织切换后，Workbench 必须核对 Session Tenant、Tenant 详情和组织清单当前项。短暂失败可有界重读；三次仍失败时禁用组织切换并强提示重新加载或刷新页面，不得静默保留旧组织。

## 5. 管理员级别调整

- 管理员可把同组织其他用户提升为管理员，或降为普通用户。
- 系统管理员在组织管理页按登录标识设置管理员：同组织启用普通用户原地提升，已有管理员幂等返回，账号不存在才创建待激活管理员和链接。
- 已激活的其他组织账号会在目标组织建立新的 Subject；系统管理员账号及不可用账号继续拒绝。
- 当前管理员不能把自己降级；每个组织至少保留一名启用管理员。
- 调整由 IAM 审计并递增目标用户 Session Generation，使其旧 Session 失效。
- 管理员只能管理组织用户，不自动获得任何业务 Capability。
- 系统管理员级别不能由组织管理员授予、撤销或修改。

## 6. 异常与恢复

- 待注册邀请可以重新生成邀请链接；成功后同类旧链接立即失效，级别和 Tenant 不变。
- 邀请无效、过期、已使用，账号已加入当前组织，既有账号原密码错误，系统管理员账号接受业务组织邀请，均稳定拒绝且不产生半成品。
- 已激活用户不再走邀请激活，只能由管理员创建一次性密码重置链接。
- 同一组织重复手机号／邮箱、跨组织直接使用错误 Subject ID、无效或过期 Token 必须稳定拒绝；相同登录账号加入不同组织是合法操作。
- 账号停用、密码重置、Session Generation、Capability 与审计仍归 IAM；Workbench 不保存用户副本或密码。

## 7. 不在第一版

- 公开注册、用户绕过有效邀请自行创建或搜索加入组织；
- 用户自行搜索、申请或批准加入组织；多组织身份仍由管理员建立；
- 自动发送短信／邮件、短信验证码登录及送达回执；
- 邀请时预设 People Person；注册后成员关联继续是独立显式操作；
- 在 IAM 用户表保存 People 成员的职位、部门、业务角色或职责；
- 由“系统管理员／管理员”名称自动推导业务权限。

## 8. 验收

- 登录页不存在创建组织入口；普通用户和管理员访问系统管理接口均为 403。
- 系统管理员完成“创建组织 → 首位管理员激活 → 管理员登录”，并能看到全部组织元数据而不能读取组织业务页面。
- 管理员创建普通用户和管理员邀请时，请求体均不含他人的姓名、手机号或邮箱；页面只显示 Tenant、级别、有效期和一次性链接。
- 手机号和邮箱各完成一次“创建邀请 → 预览 → 本人注册 → 用后拒绝 → 登录”；重签后旧链接拒绝。
- 既有账号用错误密码接受失败且组织列表不变；用原密码接受后增加一个独立 Subject，原密码继续可登录两个组织。
- 新增普通用户和管理员各一名，列表明确显示用户姓名、登录账号、用户级别、状态和允许动作。
- 提升／降级使旧 Session 失效；本人自降级、最后管理员移除、跨组织目标和组织管理员授予系统管理员均稳定拒绝。
- 系统管理员为既有普通用户设置管理员后 Subject ID 不变，页面明确显示“已提升”；重复设置显示“已经是管理员”，不重复写审计或生成激活链接。
- 管理员修改组织显示名称后 GET `/api/v1/tenant` 立即读回新名称，Tenant ID 不变且只有一条改名审计；普通用户和系统管理员越权修改均失败。
- People 成员档案与 IAM 用户分别创建、停用和查询，互不改写；建立关联后仍通过稳定 ID 分域读取。
- migration 重放、IAM Go 测试／vet、Workbench Go 测试／vet、前端语法检查和文档链接检查通过后，才可进入部署候选。
