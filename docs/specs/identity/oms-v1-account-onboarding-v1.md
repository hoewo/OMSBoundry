# OMS1 用户开通与组织管理 V1

日期：2026-10-27
状态：BF-272 账号激活、BF-275 用户级别／系统管理页／组织创建已发布；BF-276 既有用户管理员挂载已随 D1 Suite `v0.1.0-test.oms-v1.41` 发布

## 1. 问题与结果

> 系统把 IAM 用户误称为“成员”，又缺少平台级组织管理入口 → 明确用户与成员是两个对象：IAM 管理系统管理员、管理员和普通用户；People & Groups 管理成员、职位、部门、业务角色与职责；仅系统管理员可以从独立页面创建组织。

## 2. 对象边界

- **用户（IAM Subject）**：能够登录和使用系统的人，拥有账号标识、密码、状态、Session 和用户级别。
- **成员（People Person）**：公司业务人员档案，拥有部门、职位、业务角色、入离职状态及业务职责。
- 用户和成员可以通过同 Tenant 内的稳定引用关联，但二者允许独立存在；不得共享密码、账号状态、管理员标记、职位或业务角色字段。
- 用户级别只有：`system_administrator`（系统管理员）、`administrator`（管理员）、普通用户。
- 财务、经营、工资等权限是独立 Capability，不是用户级别；未来的“财务负责人”等也不能扩成第四种用户级别。

## 3. 系统管理员与组织创建

1. 系统管理员登录后只进入独立系统管理页，不直接进入组织业务工作台。
2. 系统管理页展示当前服务器全部组织的稳定 ID、名称、状态、用户数量、管理员数量、创建时间和必要运维状态，不展示工资、财务、项目等业务事实。
3. 只有系统管理员可点击“创建组织”；登录页不提供公开创建入口。
4. 创建时填写组织名称、首位管理员姓名及手机号或邮箱。
5. IAM 在单一事务中建立 Tenant、首位 `pending` 管理员用户、24 小时一次性激活 Token 与不可变审计；任一步失败不得留下半个组织。
6. 系统管理员复制激活链接并通过可信渠道交给首位管理员；本人设置密码后激活。
7. 首版一个用户只属于一个组织，不提供租户切换。

## 4. 组织用户新增与激活

1. 管理员在“账号与租户”页面点击“新增账号”。
2. 管理员填写用户姓名、手机号或邮箱，并选择“普通用户”或“管理员”。
3. IAM 建立 `pending` 用户并返回 24 小时一次性激活链接。
4. Workbench 只在本次结果显示完整链接，并提供复制操作；没有短信或邮件提供商时不得显示“已发送”。
5. 本人通过链接设置 12～72 位密码，IAM 原子激活用户并立即作废链接。
6. 本人以后使用手机号或邮箱加密码登录；历史用户名继续兼容。

## 5. 管理员级别调整

- 管理员可把同组织其他用户提升为管理员，或降为普通用户。
- 系统管理员在组织管理页按登录标识设置管理员：同组织启用普通用户原地提升，已有管理员幂等返回，账号不存在才创建待激活管理员和链接。
- 其他组织账号、系统管理员账号及非启用账号不能被这一入口迁移、覆盖或重复创建。
- 当前管理员不能把自己降级；每个组织至少保留一名启用管理员。
- 调整由 IAM 审计并递增目标用户 Session Generation，使其旧 Session 失效。
- 管理员只能管理组织用户，不自动获得任何业务 Capability。
- 系统管理员级别不能由组织管理员授予、撤销或修改。

## 6. 异常与恢复

- 待激活用户可以重新生成激活链接；成功后同类旧链接立即失效。
- 已激活用户不再走邀请激活，只能由管理员创建一次性密码重置链接。
- 重复手机号／邮箱、跨组织用户 ID、无效或过期 Token 必须稳定拒绝。
- 账号停用、密码重置、Session Generation、Capability 与审计仍归 IAM；Workbench 不保存用户副本或密码。

## 7. 不在第一版

- 公开注册、用户自行创建或搜索加入组织；
- 同用户加入多个组织、租户切换；
- 自动发送短信／邮件、短信验证码登录及送达回执；
- 在 IAM 用户表保存 People 成员的职位、部门、业务角色或职责；
- 由“系统管理员／管理员”名称自动推导业务权限。

## 8. 验收

- 登录页不存在创建组织入口；普通用户和管理员访问系统管理接口均为 403。
- 系统管理员完成“创建组织 → 首位管理员激活 → 管理员登录”，并能看到全部组织元数据而不能读取组织业务页面。
- 手机号和邮箱各完成一次“新增 → 重签 → 旧链接拒绝 → 新链接激活 → 登录”。
- 新增普通用户和管理员各一名，列表明确显示用户姓名、登录账号、用户级别、状态和允许动作。
- 提升／降级使旧 Session 失效；本人自降级、最后管理员移除、跨组织目标和组织管理员授予系统管理员均稳定拒绝。
- 系统管理员为既有普通用户设置管理员后 Subject ID 不变，页面明确显示“已提升”；重复设置显示“已经是管理员”，不重复写审计或生成激活链接。
- People 成员档案与 IAM 用户分别创建、停用和查询，互不改写；建立关联后仍通过稳定 ID 分域读取。
- migration 重放、IAM Go 测试／vet、Workbench Go 测试／vet、前端语法检查和文档链接检查通过后，才可进入部署候选。
