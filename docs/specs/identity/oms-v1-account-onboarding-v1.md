# OMS1 账号录入与激活 V1

日期：2026-10-26  
状态：已接受，实施中

## 1. 问题与结果

> “邀请账号”只有一个用户名表单、没有明确送达方式，管理员无法判断账号是否真的发给了成员 → 管理员直接录入成员的手机号或邮箱，系统明确生成一次性激活链接，由管理员通过可信渠道交给本人，本人设置密码后再登录。

## 2. 第一版流程

1. 租户管理员在“账号与租户”页面点击“新增账号”。
2. 管理员填写成员姓名，并在手机号和邮箱中选择一种主登录账号。
3. IAM 规范化并校验登录账号，建立 `pending` Subject，同时返回一条 24 小时有效的一次性激活链接。
4. Workbench 只在本次结果中显示完整链接，并提供“复制链接”和“复制完整通知”；没有短信或邮件提供商时不得显示“已发送”。
5. 管理员通过企业微信、当面或其他可信渠道把链接交给本人。
6. 本人在链接页面设置 12～72 位密码；IAM 原子激活账号并使链接立即失效。
7. 本人以后用已录入的手机号或邮箱加密码登录。历史用户名账号继续兼容登录，但新增页面不再要求管理员创造用户名。

## 3. 异常与恢复

- 待激活账号可以“生成新激活链接”；新链接生成成功后，同类旧链接立即失效。
- 已激活账号不允许重新走邀请激活，只能由管理员创建一次性密码重置链接。
- 手机号／邮箱已经被其他 Subject 使用时拒绝新增；首版一个登录账号只对应一个 Tenant，不提供同账号多租户选择。
- 账号停用、密码重置、Session Generation、Capability 和审计继续由 IAM 拥有；Workbench 不保存账号副本或密码。
- 未配置短信／邮件提供商时，只提供复制交付，不记录虚假的发送时间、送达状态或短信验证码。

## 4. 数据和接口兼容

- IAM 继续使用既有 `subjects.username` 作为稳定存储字段，迁移只扩展其规范值为大陆手机号、邮箱或兼容用户名，不重写已存在 Subject ID 和业务引用。
- 邀请接口兼容旧 `username` 字段，并优先接受语义明确的 `login_identifier`。
- 新增管理员重新签发激活链接命令；操作必须处于相同 Tenant、目标为 `pending`，并写入不可变审计。
- 一次性 Token 原文只在创建结果返回，数据库只保存 SHA-256；链接中的 Token 放在 URL fragment，不进入服务端访问日志和查询参数。

## 5. 不在第一版

- 自动发送短信或邮件、短信验证码登录、送达回执和消息模板平台；
- 公共注册、成员自行加入组织、同账号加入多个租户及租户切换；
- Workbench 自建账号表、绕过 IAM 的直接录入或管理员代设成员密码。

## 6. 验收

- 手机号和邮箱各完成一次“新增 → 重签 → 旧链接拒绝 → 新链接激活 → 登录”；
- 同租户列表明确显示姓名、登录账号类型、状态和可执行动作；
- 非管理员不能读取租户 Subject 列表或执行新增、重签、停用、重置；
- 重复手机号／邮箱、非法格式、跨租户 Subject ID、已激活账号重签均稳定拒绝；
- 登录页默认展示手机号／邮箱密码登录，不把未接通的验证码流程作为主入口；
- migration 重放、IAM Go 测试／vet、Workbench Go 测试／vet、前端语法检查和文档链接检查通过后，才可进入部署候选。
