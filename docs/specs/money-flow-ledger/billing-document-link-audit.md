# Money Flow Ledger：Billing Document 与 Billing Link 边界审计

里程碑：M4  
候选编号：MF-M4-007  
日期：2026-09-20  
状态：边界审计完成，功能延期；未进入实现

## 审计目的

判断 OMS 雏形、已完成度较高的 OA 项目和 BizFoundry 讨论材料，是否足以定义一个小而完整的票据登记与义务匹配闭环。

本审计不是 Billing Document 功能规格，不承诺数据库、接口或页面。当前 Money Flow 运行时不存在票据事实，也不能使用 Obligation、Cash Transaction、Allocation 或文件 Evidence 冒充票据。

## 能够保留的稳定事实

- 票据回答“开具或收到过什么凭据”，Obligation 回答“应该收付多少”，Cash Transaction 回答“实际收付了多少”；三者必须分开；
- 开票或收票本身不创建、冲减或关闭 Obligation，也不证明资金已经发生；
- 真实业务会多次开票、分次收付款，历史记录不能被后一次操作覆盖；
- 至少存在 `issued` 与 `received` 两个方向候选，票据需要正金额、币种、发生日期、开具方、接收方和可选文件证据；
- 票据与 Obligation 若建立关系，必须是独立 Billing Link，不能直接把发票挂到 Cash Transaction 上替代义务账；
- 税率、抵扣、申报、会计凭证和外部开票平台不属于当前 Money Flow 内核。

这些事实足以划清边界，但不足以形成可执行、可纠错的写入模型。

## 参考材料能够证明什么

### OMS 雏形

OMS 只提供一个“我方向甲方开票”的展示样例，并确认一份甲方合同可以有多张发票和多笔回款。税率、税点承担、税额计算、抵扣、申报以及外部发票平台均明确待确认，原型字段只用于展示。

它能证明开票、应收和回款需要分开，但不能证明票据类型、唯一编号范围、收票流程、作废／红冲／更正方式或 Billing Link 金额口径。

### OA 已实现项目

OA 同时出现我方开票和对方开票，并支持金额、日期、往来方、说明和附件。这能佐证双向登记和文件证据的现实价值。

但 OA 将奖金、成本、支付和发票合并为 `FinancialRecord`，金额使用浮点数，记录允许编辑／删除，发票通过单个自引用直接关联付款。实现中没有独立票号、币种、票据状态、作废／红冲／更正事实，也没有票据与义务的多对多关系。因此只能把它作为反例和业务动作来源，不能复制其模型。

## 方案审计

### 方案 A：复制 OA 的 FinancialRecord 发票类型

否决。它混合票据与资金，依赖项目和行业费用类型，使用可空字段与浮点金额，并允许直接编辑历史；这些行为都会破坏已经验证的 Money Flow 事实边界。

### 方案 B：先建立通用发票表，后补状态和关系

否决。票号唯一范围、作废／红冲和更正语义决定表约束与不可变链；先建表会把未知选择固化成数据库事实。

### 方案 C：只登记票据，不实现 Billing Link

当前不进入实现。它可以保存孤立附件和金额，却不能完成计划中的“票据与义务匹配”闭环，也无法验证多对多和错误撤销；这会把完整功能人为缩成一个低价值表单。

### 方案 D：把票据直接关联 Cash Transaction

否决。OA 的一对一关联只能反映某个客户流程，无法解释未付款票据、预收款、合并付款或一张票据覆盖多个义务；它也会绕过 Obligation 与 Allocation。

## 当前决定

1. `MF-M4-007` 在边界审计后延期，不创建 migration、领域类型、HTTP 入口、页面或票据汇总；
2. 当前余额、Allocation 和 Closure 公式不引入任何“已开票／已收票”假设；
3. 不使用 Cash Transaction、Allocation、Evidence 或自由文本标签冒充 Billing Document／Billing Link；
4. OMS 的税率与税额仍是待确认原型信号，OA 的一对一付款关联仍是客户定制实现，不提升为 BizFoundry 内核事实；
5. 下一切片转向只依赖现有 Obligation、Due Date 和余额事实的逾期／账龄投影；
6. 获得真实票据纠错和多对多匹配案例后，先形成正式规格与 ADR，再重新进入实现。

## 重新进入实现的最小证据

至少需要一组真实业务样例，覆盖：

- 一张票据匹配多个 Obligation、一个 Obligation 被多张票据匹配，以及每条 Link 的金额；
- 票据号码的实际唯一范围和重复录入处理；
- 正常票据、作废、红冲、更正以及错误 Link 撤销的完整时间线；
- issued 与 received 各一例，并说明第三方开票是否允许；
- 含税金额、税额和可匹配金额之间的明确关系；
- 文件证据、操作者、业务日期、外部平台状态和可信程度。

这些信息出现前，延期比制造一个名称通用、行为却无法验收的发票模块更符合“小而精、稳定可用”的目标。
