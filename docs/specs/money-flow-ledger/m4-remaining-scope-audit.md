# Money Flow Ledger：M4 剩余范围边界审计

日期：2026-09-20  
功能编号：MF-M4-AUDIT-001  
状态：accepted

## 1. 审计目的

在继续扩展 Money Flow Ledger 前，判断 M4 尚未闭合的预收／预付与超额、通用表格导入、日期预测，以及已经延期的坏账、票据和真实退款中，哪些内容已有足够稳定的业务事实可以实现，哪些内容必须等待真实案例。

本审计只接受当前代码事实、已经确认的 BizFoundry 不变量和参考项目中可重复出现的业务信号。OMS 浅层雏形和 OA 定制流程都不能直接成为本项目的产品事实。

## 2. 审计结论

| 候选范围 | 当前已有的稳定事实 | 结论 |
| --- | --- | --- |
| 预收／预付／超额 | Cash Transaction 可以先于 Obligation 独立登记；Allocation 同时受资金可分配余额和义务剩余金额约束；分配后的剩余资金继续以 unallocated 展示并可后续分配 | v1 已具备安全的“未分配实际资金”处理；不能把它自动命名为预收、预付、保证金或其他会计分类 |
| 通用表格导入 | 参考材料只说明历史导入需要截止日、批次、源文件、校验状态和确认依据 | 延期；格式、业务键、部分失败、冲突与纠错语义尚未定义。只有将来启用导入时，才要求重复批次不重复记账 |
| 日期预测 | 到期日和预计收付款日回答不同问题；参考材料反复出现独立的预计收款／付款日期 | 进入 `MF-M4-015`：实现可追溯的预计现金日期，以及按查询时当前未结余额形成的预计流入／流出排期 |
| 坏账 | 未定义预计可收回额、转回和追回款 | 保持延期，见 `MF-M4-005` 审计 |
| Billing Document／Billing Link | 未定义票据生命周期、唯一范围、匹配金额与撤销 | 保持延期，见 `MF-M4-007` 审计 |
| 真实退款／退回款 | 未定义其对原 Allocation、Obligation outstanding 与 Closure 的影响 | 保持延期，见 `MF-M4-010` 审计 |

## 3. 预收／预付与超额的安全边界

当前系统允许实际资金独立于义务存在，并且不会为了“对平”而强迫用户创建虚假义务：

```text
登记实际收款／付款
  → 可暂时没有对应 Obligation
  → Cash Transaction 保持 unallocated
  → 以后出现真实义务时再由 Allocation 明确核销关系
```

一笔资金大于当前义务剩余金额时，Allocation 只能使用义务可接受的部分，剩余资金仍属于原 Cash Transaction 的 unallocated。这个行为足以支持“不丢失、不超分、可后续处理”的操作闭环。

当前不做以下推断：

- 未分配收款不自动等于预收账款；
- 未分配付款不自动等于预付账款；
- 超额不自动等于赠款、保证金、押金、手续费或退款；
- 不自动创建反方向义务，也不自动改变往来方余额；
- 不生成会计科目、凭证或税务含义。

若真实客户需要这些分类，必须先提供分类形成、转化、退回、冲销和报表口径的完整案例，再设计独立事实，不能覆盖 Cash Transaction 或 Allocation。

## 4. 通用表格导入为何延期

一个可交付导入功能至少还需要确定：

- 导入对象是 Party、Obligation、Cash Transaction 还是历史余额；
- 源文件、批次 ID、截止日和确认人的权威性；
- 每行稳定业务键以及同一批次重放规则；
- 格式错误、业务冲突和部分失败是否允许提交；
- 已导入事实如何更正，是否只能追加调整／冲销；
- 导入后的人工复核状态和原文件保留方式。

在这些内容未定义前，新增一个“上传 Excel 后直接写表”的入口会绕过现有命令幂等、不可变事实、审计和纠错边界，因此不实现。

M4 的退出门槛解释为：**如果某一版本启用了导入，同一稳定批次或业务键的重复提交不得重复记账**。当前 v1 不以一个未定义的通用导入器作为交付阻塞项。

## 5. 日期预测的可实现最小语义

`due_on` 是义务条款中的到期日；`expected_on` 是管理员基于当前经营判断记录的预计现金发生日。两者必须长期分开：

- 到期日变化需要 Obligation revision；
- 预计日期变化追加独立 Expectation sequence；
- 预计日期不改变义务金额、状态、到期日或历史余额；
- 当前预计金额始终取查询时该义务的 current outstanding；
- 部分 Allocation 或 Remission 后，预计金额自动随 current outstanding 减少；
- outstanding 为 0 或义务关闭后，不再进入当前预计排期，但历史 Expectation 仍保留；
- 未设置预计日期的 open 正余额必须单独显示为“未排期”，不能静默使用到期日代替；
- 汇总必须按本方账簿主体、方向和币种隔离，不做跨币种相加；
- 该投影不是银行账户余额、利润、流动性缺口、承诺付款或会计现金流量表。

## 6. 下一实现切片

`MF-M4-015` 只交付：

1. 对 open 且当前未结余额大于 0 的 Obligation 设置或更新预计现金日期；
2. 通过追加 `set`／`clear` 事实保留完整变更历史；
3. 以 Command ID、规范化负载和可信 Actor 提供幂等与审计；
4. 展示按预计日、本方主体、方向和币种隔离的当前排期；
5. 单列未排期的 open 正余额；
6. 从台账导出中带出完整 Expectation 历史。

分期计划、单条义务多日期拆分、概率、计划金额覆盖、银行余额起点、资金缺口、自动推算和审批均不在本切片内。
