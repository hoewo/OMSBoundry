## 1. 结论

OMS 一期项目详情已从原来的稀疏摘要补齐为可用于真实业务评审的完整经营投影，并已发布到公网正式验收入口。此次完成的是产品设计中“项目详情”的全部既定范围，不等于把审批、内部成本、催收、项目进度或会计总账加入一期。

页面按以下顺序呈现：

1. 项目名称、开启日期、甲方、施工方数量和最近更新时间；
2. 甲方侧：应收总额 → 累计开票金额与笔数 → 实际回款 → 未回款；
3. 施工方侧：应付总额 → 累计收票金额与笔数 → 实际支付 → 未支付；
4. 每个施工方的合同状态、附件数量和四项独立金额汇总；
5. Contract 正式金额变更；
6. Project revision 历史、项目说明、创建时间和当前 revision。

具体开票、收票、回款和支付流水没有重复塞入项目详情，也没有在项目详情增加相同的业务新增按钮。它们继续由对应专业模块提供列表、筛选、详情和登记能力。这是为了保持项目页一眼能读懂，而不是缺项。

## 2. 数据与边界

- Project Workspace：项目身份、甲方关系、施工方资源关系、创建／更新时间和 revision 历史；
- Contract Ledger：上下游合同、合同状态、正式金额变更和合同业务引用；
- Billing Invoice：上游开票、下游收票的有效金额与笔数；
- Money Flow Ledger：实际回款、实际支付、已核销与余额；
- Party Directory：甲方和施工方当前档案；
- Evidence Service：合同附件数量与访问入口。

Workbench 只在请求时按稳定 ID 组合这些事实。此次没有新增 OMS 数据库、schema、migration、Grant、共享业务表、跨库读取或新的业务事实 Owner；金额聚合使用整数最小货币单位和 `BigInt`，未引入二进制浮点误差。
