# OMS 一期新增与项目汇总反馈验证（2026-10-14）

## 结论

本轮关闭了两个会直接误导使用者的问题：长时间打开 OMS 页面后新增甲方／施工方会因短期 Capability Credential 失效而失败；主体即使保存成功，在尚未关联项目时也会从对应管理页消失。项目开票与回款原本已经进入 Owner 并计入项目汇总，但详情只显示金额、沿用项目资料更新时间，用户无法确认新记录是否真的生效。

修复已发布到 `oatest.antuinfo.cn`。Unified Workbench 版本为 `v0.1.0-test.oms-v1.12`，镜像摘要为 `sha256:a9759a92300718a0851c20a619406992a16e5fdfa198315fcb7de9e12c2f0f31`。正式 D1 `check` 通过，部署后 Workbench、Gateway、IAM、Nginx、PostgreSQL 和各业务 Owner 均为 healthy。

## 根因与修复

### 1. 长期开页后的新增失败

Workbench 曾把“本页面已经为某应用换过一次凭证”缓存为永久授权状态；应用短期凭证过期后，新增仍直接请求 Owner，Gateway 返回 `credential_required`，页面只显示“需要重新进入该应用”。

现在所有 `POST`、`PUT`、`PATCH`、`DELETE` 在发送前都重新经过 Gateway 换取短期应用凭证。读取请求只在 Gateway 明确返回入口凭证失效或入口重定向时重新授权一次；普通 401／403、业务校验失败和冲突不会被自动重试，避免重复写入或掩盖真实拒绝。

### 2. 主体保存后不可见

Party Directory 只拥有主体档案，不拥有永久“甲方／施工方”角色；角色由项目关系确定。原页面却只显示已经被项目使用的 Party，导致刚创建的主体虽然保存成功，也会从管理页消失。

甲方管理和施工方管理现在都显示全部可选主体，并明确标记“已作为甲方／施工方关联 N 个项目”或“待关联为甲方／施工方”。这只是两个项目关系视角，没有给 Party 主档增加角色字段，也没有复制主体事实。

### 3. 开票／回款在项目详情不清楚

项目详情仍按稳定 Project ID 从 Billing 和 Money 实时聚合，不新增流水副本。四个节点现在同时显示金额、有效记录笔数和最近业务日期；页头显示“最近票款”，项目本身的 `updated_at` 改名为“项目资料更新”，避免把项目资料时间误认为票款更新时间。新增开票／收票／回款／支付后的保存反馈也会直接回显该项目的新累计值和笔数。

### 4. 普通刷新仍可能使用旧脚本

首次发布后，服务器制品已经更新，但 OMS CSS／JS 查询版本仍沿用上一轮值，浏览器普通刷新可能继续命中旧缓存。最终发布把资源查询版本递增到 `20261014.2`，使新 HTML 自然请求新制品，不要求用户手工清缓存或强制刷新。

## 其余范围检查

OMS 一期全部业务写入——项目、主体、合同版本、施工方关系／应付、开票／收票、回款／支付及附件关联——都统一经过同一个 `api`／`evidenceFetch` 授权封装，因此本轮凭证修复覆盖这些入口，而不是只给甲方按钮打补丁。代码中没有绕开该封装的业务写入。

本轮没有新增 Owner、表、schema、Grant、角色字段或项目内流水列表；也没有改变发票与资金不强制一一核销的一期边界。票款明细仍在各自专业入口，项目详情只展示可读汇总。
