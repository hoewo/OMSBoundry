## 原站依据与边界

只读参考提交 `826e0fc65aa09947fc4f64f62a2644fa5d11a302`，原工作树仍干净。核对 `ProjectList.tsx`、`projectListRestore.ts`、`ProjectDetail.tsx` 及后端编号解析／目录查询：默认年份视图、Enter 提交搜索、分页 10 条、包作为一项、子项匹配保留包、返回时恢复列表上下文。年份来自项目编号而非承接日期，序号按精确整数处理。

[Project Directory v1](../../arckit/spec/project-workspace/directory.md) 是 Project 自有只读 API，旧列表契约保持不变。每页 1～100 个可见根，repeatable-read／read-only 事务内读取根、子项、当前负责人及 total；仅 `active` 且当前可信 Tenant／Resource Scope 内的项目可见。子项单独授权，父项不可见时作为可见根；详情父／子摘要也补同一 Scope 过滤。关键词是字面包含，不将 `%`／`_` 当通配符。不读其他应用表，不写 revision／历史，负责人只使用已有 Assignment 快照。

页面串行读取目录分页，检查 total、重复 ID、层级及进度，异常明确要求重读，不能静默当作完整列表。跨页不是全局冻结快照，未证明大型客户容量。OA 年份解析只在版本化参考界面层；未按年份编号的项目额外列明，避免原年查询隐藏无编号包，这项安全差异尚需原站真人复核。sessionStorage 仅保存租户＋账号隔离的搜索／页码／展开／滚动，不保存业务事实或凭证。

前端技能用于比对原流程与实际滚动容器，没有另创操作体系；文档技能按仓库既有格式同步决策和证据。经营／生产进度投影尚未接通，明确标记而非填入演示值。
