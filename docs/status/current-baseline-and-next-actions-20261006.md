## 1. 当前状态以什么为准

当前实现状态以仓库根目录 `AGENTS.md` 的“产品边界”和“当前下一阶段主线”为准。后续实验曾产生大量代码、报告、验收脚本和运行记录；它们可以保留为候选实现与历史证据，但在与 `AGENTS.md` 冲突、未进入干净可追溯基线、长期证据不完整或中途被停止时，不得继续描述为当前已完成能力。

BF-120 只修正实现完成度，不撤销与当前基线一致的数据所有权、版本化契约、IAM、Evidence、精确金额、追加历史、Suite Manifest、Deployment Profile 和边界收敛原则。旧证据不删除，后续按“可直接保留／需复验／延期／放弃”四类重新归档。

## 3. 旧实验如何处理

1. 保留代码、报告、结构化回执和失败记录，不批量删除。
2. 架构与所有权结论只有在不违反 `AGENTS.md` 和 BF-120 时继续有效。
3. BF-068～BF-072 以及 BF-083～BF-119 中关于“已实施／已通过／下一切片”的文字，先降级为历史候选状态；对应功能只有重新映射到当前 C1～C8 门禁并复验后，才能恢复完成状态。
4. `/tmp` 路径、临时容器、已停止恢复栈、未跟踪报告或无法从当前工作树复演的结果，只能作为线索，不能单独支持当前完成结论。
5. 不从中断点机械续跑旧脚本；先确认当前源码、schema、契约、依赖和证据仍匹配，再决定复用或重做。
