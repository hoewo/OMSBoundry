# OMS 一期试用问题处理记录（2026-10-20）

本记录只跟踪试用反馈、确认结论与实现状态。未确认的问题不得直接解释为产品规则。

## 已确认、实现并发布

1. 项目列表把“项目开启日期”从项目名称单元格中拆出，作为独立列；项目名称保持单行。
2. 项目详情不展示无操作意义的合同“草稿”标签；底层 Contract 状态不改写，其他有判断价值的状态仍可展示。
3. 项目详情在甲方板块增加默认收起的“开票明细”，在施工方板块增加默认收起的“收票明细”；仅只读展示，不增加新增或编辑入口。
4. 应收管理把项目与甲方拆成独立列；两个字段均保持单行，超长内容省略并可悬停查看全文。
5. 应收管理“已回款”列只显示金额，不再在金额下方重复显示“已回款”标签。
6. 导出窗口直接提供筛选：开票、收票、回款、支付按项目、起止日期和记录状态；应收、应付按项目、甲方／施工方和资金状态。窗口实时展示预计条数，导出不受列表分页限制。
7. 各业务列表保留紧凑搜索框和单个筛选按钮，不增加常驻筛选栏；项目按甲方、施工方、回款状态和支付状态筛选，应收／应付按项目、甲方／施工方和资金状态筛选，票据与资金按项目、日期范围和记录状态筛选。筛选按钮显示生效条件数量，项目搜索同时覆盖项目名称、甲方、施工方和项目说明。
8. 列表排序直接放在有判断价值的表头上，不增加独立排序面板。项目默认按开启日期倒序，应收／应付保持业务关系建立时间倒序，票据与资金分别按开票、收票、回款和支付日期倒序；名称、日期和金额表头可在升序／降序间切换，备注与操作列不排序。金额使用精确整数值比较，不使用格式化文字或二进制浮点数。
9. 正常页面不再显示 Money、Evidence、Owner、Party ID、revision、路由、事实所有者等实现说明；侧栏底部、票据方向提示和表单中的架构说明已移除。失败时只显示刷新、重试或联系管理员等可执行信息；金额异常、重复名称、自开自收和权限等真实业务提醒保留。
10. 不再使用含义模糊的“业务日期”：开票使用“开票日期”，施工方发票使用“收票日期”，回款使用“回款日期”，支付使用“支付日期”；列表、详情、新增／更正、筛选和导出保持一致，项目继续使用“项目开启日期”。
11. 2026-10-21 经用户进一步确认，项目列表不再展示应收、未收、应付、未付金额，改为“应收状态／应付状态”，正常只显示“已完成／未完成”；超额收付或负余额继续明确显示“金额异常”。精确金额保留在项目详情及应收／应付专业模块。
12. 项目详情继续使用独立完整页面；其他简单详情、新增、编辑、筛选和导出统一改为居中业务弹窗，纯查看只保留关闭，手机端使用全屏弹窗；文件预览保持独立预览层。

## 暂缓
